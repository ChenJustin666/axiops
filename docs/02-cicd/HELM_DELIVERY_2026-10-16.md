## 第 1 项的实际行为

工作流运行详情选择 Helm 部署节点的日志，可读取以下阶段；回滚节点使用同一运行日志入口。运行中的后端须先配套更新才会产生新日志，历史任务不会补写。

```text
[prepare] 正在读取目标环境的 Helm Chart 和 values
[target] 集群 #2 · 命名空间 qa · Helm Release api
[prepare] Chart 渲染及资源范围校验通过，部署快照已保存
[waiting] 正在安装或升级 Helm Release；等待资源就绪，超时 600 秒；失败由 Helm 执行原子清理或恢复
[success] Helm Release api 已就绪 · revision 3
```

准备、目标与等待日志通过已有 Worker 回调先持久化，再调用 Helm。日志存储不可用时不继续发起安装/升级/回滚。最终成功只在 provider 确认完成并写入有效 revision 后输出。失败由 Worker 保留原因；恢复中的任务记录继续核对原操作，不重复提交，不提前显示成功。

Helm 回滚会产生一个新的 Release revision，并记录恢复自哪个旧 revision。同步返回或恢复返回的 revision 为 0/负数均不标记成功。

日志不整份保存 Chart、环境 values、Secret 或 Helm SDK debug 内容。恢复失败的日志复用现有诊断脱敏；这不等于任意应用错误文本都能自动识别全部敏感值。

这一项没有新增 Pod/事件周期采集。SDK 等待期间可看到等待阶段，不能据此声称页面已显示每个 Pod 的最新异常或自动恢复已验收。
