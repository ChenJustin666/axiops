# AxiOps CI/CD 页面需求（严格按参考图实现）

## 1. 实现原则

- 页面结构、信息位置、操作顺序、间距和主色按用户提供的 Zadig 页面参考实现。
- 品牌、Logo、产品名和文案统一使用 AxiOps，不复制 Zadig 品牌资产。
- 只保留 AxiOps 需要的三类交付：K8s YAML、Helm Chart、主机应用。
- 权限、代码源、Revision、环境绑定、构建和工作流继续使用 AxiOps API，不引入 Zadig Vue 2 运行代码。
- 不在页面中增加参考图没有的营销文案、大卡片、统计区或装饰性模块。

## 2. 页面顺序

```text
项目列表
  -> 全屏创建项目
  -> 项目交付向导
       第一步 项目配置
       第二步 创建服务
       第三步 加入运行环境
       第四步 工作流交付
```

## 3. 项目列表

- 保留 AxiOps 左侧主导航和顶部栏。
- 内容区使用白色背景，顶部为项目分类、搜索和右侧“新建项目”。
- 项目以规则卡片网格展示；卡片只展示类型图标、名称、标识、描述和必要状态。
- 不展示无关运营数据，不把代码源或环境配置放进项目卡片。

## 4. 全屏创建项目

- 点击“新建项目”打开全屏页面，而不是 680px 普通弹窗。
- 页面主体为居中的窄表单，标题“开始新建项目”。
- 字段顺序固定为：项目名称、项目主键、描述信息、项目特点。
- 项目主键默认根据项目名称生成，允许在创建前编辑，创建后不可修改。
- 项目特点按行展示：
  - 基础设施：Kubernetes / 主机。
  - Kubernetes 服务部署方式：K8s YAML / Helm Chart。
- 底部固定操作区只有“取消”和“立即创建”。
- 创建成功直接进入项目交付向导，不在本页填写 YAML、仓库、集群、变量或工作流。

## 5. 项目交付向导壳

- 顶部显示“产品交付向导”和四步横向 Step：项目配置、创建服务、加入运行环境、工作流交付。
- 当前步骤下方显示蓝色步骤标题块和一句说明文字。
- 右侧可显示项目已有环境的小型纵向状态，不将环境做成顶部彩色 Tag 列表。
- 页面底部固定白色操作栏，右侧为“上一步/下一步”。

## 6. 第二步：创建服务

- 主体直接进入服务编辑区，不先显示整页的来源卡片。
- 三栏位置固定：
  - 左栏约 250px：服务树、创建按钮、服务状态、搜索。
  - 中栏初始约 500px，可自适应：YAML/Helm 文件编辑器、校验结果、保存按钮。
  - 右栏最小约 372px：服务组件、镜像、系统变量、服务变量和构建入口。
- 没有服务时，中间显示简单空状态和圆形“+”按钮。
- 点击创建服务后弹出来源选择，只有：手工输入、从代码库同步、使用模板新建。
- 选择来源后再填写该来源需要的字段，不将三个来源的字段同时铺在页面上。

## 7. 手工输入服务

- 先填写服务名称，随后进入三栏编辑页。
- 中栏直接编辑 YAML，支持多文档、行号、格式化和错误列表。
- 保存后生成不可变 Revision，左侧服务状态更新为已保存。

## 8. 从代码库同步

- 选择平台统一维护的代码源、仓库和分支。
- 支持选择单个服务目录，也支持同级目录批量导入多个服务。
- 单服务模式选择一个或多个 YAML 文件；多服务模式将每个一级子目录解析为一个服务。
- 固定 Commit 创建 Revision；后续 Webhook 同步生成新 Revision，不覆盖历史版本。

## 9. 使用模板新建

- 第一屏为模板列表，选中模板后右侧或下方显示只读模板预览。
- 下一屏填写服务名称和变量。
- 变量表格展示变量名、默认值、当前值和说明；至少支持 `cmd`、`cpuLimit`、`memoryLimit`、`port`、`replicas`。
- 编辑变量时同步刷新 YAML 预览，确认后生成服务 Revision。
- 模板页面不要求填写 Git 仓库。

## 10. 第三步：加入运行环境

- 顶部使用环境标签页，例如 dev、qa；可新增和移除，不强制四套环境。
- 每个环境配置集群、Namespace、是否生产、是否审批、环境变量和加入的服务。
- 服务列表来自第二步创建结果，可全选或单独选择。
- 只有加入环境的服务才成为该环境发布目标。
- 页面显示全局变量和环境变量区域，Secret 只选择凭据，不回显明文。

## 11. 第四步：工作流交付

- 展示由项目服务生成的工作流以及构建、测试、部署节点。
- 用户选择环境和服务后运行，运行态按服务与环境展开 Job。
- 展示 Commit、代码变更链接、构建配置快照、日志、制品 digest、部署目标和失败原因。
- 同一个制品在不同环境间晋升，不为每个环境重复构建。

## 12. 验收顺序

1. 项目列表与全屏创建项目页视觉对齐。
2. 第二步向导壳和三栏服务编辑页对齐。
3. 三种服务来源弹窗、模板预览和变量联动完成。
4. 环境标签页、服务绑定和变量页完成。
5. 工作流列表、运行详情和日志完成。

每完成一项均执行 Prettier、ESLint、Vue 模板编译和 Vite 生产构建，并记录 SQL 与重启要求。
