# 测试节点与发布策略

更新时间：2026-09-08

## 测试节点

测试节点是工作流 DAG 中的门禁节点，默认位于构建之后、部署之前。节点配置包括命令、工作目录、超时、重试、测试报告和允许失败策略；节点名称在工作流内必须唯一。

```text
checkout -> prepare -> build -> test -> approval -> deploy -> notify
```

不同服务可以并行构建和测试；测试失败时，依赖该节点的部署任务不会启动。运行详情按 `run -> service -> task -> phase` 展示日志和结果。

### 当前实现

- 后端注册 `TestExecutor`，通过 `TestCommandRunner` 接口隔离执行实现。
- 解析运行快照中的测试命令和工作目录，限制命令长度为 1 到 16384 字符。
- 捕获标准输出和错误输出，保留有界尾部并将失败原因写入任务结果；成功后返回 `succeeded`。
- 工作流单元测试覆盖成功、失败和缺少命令。

### 生产安全要求

当前 `ShellTestRunner` 仅适合本地开发和受控联调。生产环境不得让 Worker 进程直接执行用户提交的 Shell。正式 runner 必须满足：

- 使用受限 Kubernetes Job、专用构建 Agent 或沙箱运行时，Worker 只提交和观察任务。
- 强制非 root、只读根文件系统、临时工作区和资源配额，设置 CPU、内存、磁盘、进程数和最长执行时间。
- 默认禁止访问控制面、数据库和内网敏感网段；网络访问按项目/测试套件显式白名单开放。
- 凭据通过短时 Secret 注入，执行结束立即删除；日志、缓存和测试报告统一脱敏。
- 工作目录只能位于一次性 checkout 工作区，禁止使用 Worker 主机任意绝对路径。
- 镜像、测试报告和缓存按项目隔离，禁止开发项目读取生产项目内容。

在上述 runner 上线前，生产发布应关闭自定义 Shell 测试节点，或只允许平台审核过的测试模板。

## 发布策略

发布策略属于环境服务覆盖，默认从项目模板继承，用户有权限时可在发布草稿中调整：

| 策略 | 适用场景 | 必要参数 |
| --- | --- | --- |
| 滚动 | 常规无状态服务 | 副本、maxSurge、maxUnavailable、健康检查超时 |
| 金丝雀 | 需要渐进放量的服务 | 阶段比例/流量、观测窗口、指标门禁、人工或自动推进 |
| 蓝绿 | 需要快速切换和回退 | preview/active 目标、切流方式、验证窗口、旧版本保留时间 |

前端只展示当前目标具备的策略：没有 Service/Ingress/Gateway、服务网格或对应流量控制器时，不提供金丝雀/蓝绿选项。策略写入发布计划和运行快照，运行过程中每个集群目标独立记录状态。

生产环境默认要求人工审批。一个批次可以包含多个服务和多个目标，但每个目标都有独立 Job、日志、审批和回滚点；任一目标失败时按批次策略暂停后续目标，不影响已成功目标的审计记录。

## 验收标准

1. 测试节点失败时部署节点保持未执行，并在运行详情显示失败命令和尾部日志。
2. 生产运行没有审批节点时创建请求被后端拒绝；审批通过后才创建部署 Job。
3. 同一服务 Revision 和镜像 digest 晋级测试、预发布、生产时不重复构建。
4. 多集群生产批次显示多个目标 Job；单目标失败可以查看日志、暂停或按已应用快照回滚。
5. 测试命令、Secret、kubeconfig、Authorization Header 不出现在日志、缓存或运行快照中。
