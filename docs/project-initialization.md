# 项目初始化与继续配置

## 创建环境

1. 新建项目并选择交付类型，创建服务并保存服务定义。
2. 进入初始化的“环境”步骤，点击“下一步”或“新建环境”。还没有环境时，表单默认填写一个 **测试环境（qa）**。
3. 不更改环境类型，就只创建测试环境。选择“生产环境”“开发环境”“预发布环境”会替换当前表单，不会额外创建测试或开发环境；选择“自定义环境”后填写名称和编码。
4. 核对集群和命名空间，再点击“创建环境”。主机项目填写主机组。默认类型不代表可以跳过运行目标的配置。
5. 配置构建并点击“下一步”，工作流根据项目中已保存的环境生成。只有一个环境就生成一个对应工作流；确实需要多个环境时，再显式添加。

打开或取消环境表单不会写入任何环境。重复点击创建有防重保护；已有环境编码不能再次提交。工作流重试会先读取已保存结果，避免上次部分成功后重复生成。

## 中途离开后继续

- 已保存的服务、YAML Revision、环境和构建配置保存在后端。可以返回项目列表，下次点击该项目继续。
- 未完成的项目会显示“待完成初始化 · 点击继续”，重新进入后按实际已保存内容找到第一个待完成步骤：
  - 没有服务，或服务尚未保存定义 → 服务配置。
  - 服务已保存，尚未创建环境或环境目标不完整 → 环境。
  - 环境已配置，构建配置未完成或无法读取 → 构建配置。
  - 上述配置已完成 → 工作流与目标。
- 可以回到前面的步骤修改；浏览器刷新会保留有效的当前步骤地址，不允许通过 URL 跳过未完成的前置步骤。
- 保存配置和切换初始化步骤会记录进度。读取失败不会被当作空项目来自动创建环境。
- 编辑器中**尚未保存**的文字不属于已保存配置。离开服务配置时沿用已有的未保存变更确认。

## 最终完成

即使四步配置已经齐全，项目仍会保留初始化状态，直到点击 **“完成配置”**。完成操作不会自动构建或部署。完成后进入日常工作区，仍可新增环境、修改配置和创建工作流。

后端会保留首次完成时间，并阻止旧页面或迟到的进度保存把已完成项目改回未完成状态。
