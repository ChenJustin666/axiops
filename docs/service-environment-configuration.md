## 操作方式

前后端响应契约：预览要求 `validated=true,saved=false`，保存要求 `validated=true,saved=true`，并核对结果包含所有目标环境且服务ID/绑定/版本/token完整。异常或不完整响应不会提示保存成功，也不会自动重试写入；需重新加载核对。42项前端测试及后端临时数据库的真实保存响应验证通过，见 `environment-config-contract-*` 日志。

最终补充验证：前端37项行为测试、修改组件ESLint通过；两个最新组件经Vite请求均HTTP200。全量类型检查仍有既有1300条诊断，本轮检查文件无匹配诊断。日志见 `local/dev/environment-config-usability-{tests,eslint,types}.log`。这些检查不替代浏览器视觉验收。

服务配置顶部选择“共享模板”或项目中的实际环境。无需离开当前服务。

- 共享模板：Kubernetes YAML 结构与默认变量；保存产生新的服务版本。已有环境固定的版本不随之改变。
- 环境配置：显示该环境选定版本、Namespace、变量及来源。勾选“覆盖”编辑环境值；取消可恢复继承。YAML 展示为只读配置预览，构建产物镜像在部署时注入。此页不代表线上运行状态。
- Helm：共享页展示 Chart 快照文件；结构更新通过仓库或模板导入。环境页按 values 标量路径覆盖，可看到 Chart 的默认标量值。不会把 Chart JSON 当成 Kubernetes YAML 保存。
- 构建配置：同一个服务共享构建命令、镜像和缓存配置，入口标明“共享”。运行环境变量与构建时变量分别管理。此轮没有新增按环境分叉的构建配置。
- 加入环境：使用共享模板页下方原有“加入环境”按钮，顶部不重复放置入口。可选择一个或多个环境及模板版本；从尚未加入的环境页也可填写变量后加入。Helm复用同一底部入口。
- 同步：先保存来源修改，再选择目标环境和模板版本/普通变量。继承项同步意味着删除目标对应服务覆盖，恢复目标自身继承链。未选字段不变。
- 预览：展示模板版本、所选字段、实际变量差异（包括新模板默认值），必要时展开前后模板内容。后端做 YAML 或 Helm 渲染检查；这是配置校验，不调用 Kubernetes dry-run 或 Apply。
- 保存：显示“配置已保存，待部署”。审批和部署仍通过工作流操作。

环境来源同步默认不勾选模板、变量或目标；明确选择要更新的内容。“选择可修改的非生产环境”快捷操作排除来源和生产环境。预览展示来源、目标名称及数量、所选内容，生产目标需勾选已核对差异后才能保存。改变任何选择都会使旧预览和生产确认失效，提交使用已预览的请求。共享页“撤销修改”恢复保存前内容，不隐藏加入环境入口。

例：测试将 port 改为 8001，仅勾选 port 同步到生产；生产的 replicas=3、数据库地址保持不变。同步模板版本时，各环境已设置的覆盖仍然优先。

不批量同步集群、Namespace、镜像、凭据引用或环境独立资源。同名凭据变量拒绝被普通变量覆盖。当前入口面向 K8s YAML / Helm，宿主机仍使用原有配置流程。

## 数据和执行规则

复用 `service_revision`、`environment_service_override`、`variable_set` / `variable_item`，无需新迁移。

- 新的读取接口不会创建变量组或环境关联；只读事务保证一次读取内部一致。
- 配置 token 覆盖服务版本、环境关联、继承及覆盖变量组修订、环境身份。保存重新检查来源和所有目标 token；任一冲突拒绝整批，不出现前一个环境已保存、后一个环境失败的部分覆盖。
- 写入由服务行锁及事务串行化，目标逐环境检查更新权限和同项目服务权限。未选择的变量和所有凭据记录保留。传统 replicas 覆盖在显式编辑该变量时转交给服务变量，避免页面改了但执行不生效。
- 预览在事务中计算并校验结果，最终回滚；提交再次验证并提交事务。请求审计关联服务 ID。网络响应丢失后重试旧 token 会要求重读；没有新增独立的同步计划历史/幂等键表。
- 普通工作流运行提交时优先采用环境绑定版本，没有绑定则使用服务当前版本。显式指定的发布版本仍支持固定版本；服务配置页发起运行标记采用环境配置。
- 新 YAML/Helm 任务保存版本和配置快照；构建期间修改配置不会改变该次部署输入。本次构建的产物在后续执行时注入。凭据只保存引用，执行时仍验证并读取当前凭据；不会将凭据密文/明文放入 Helm 快照。
- 执行前重新检查服务归属与环境目标。集群/Namespace 等目标改变会拒绝旧运行，要求重新提交。历史没有快照的任务保留旧兼容路径。
- 对外工作流详情/运行列表去掉内部冻结配置，避免扩大配置数据的可见范围。

接口：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/v1/environments/:id/services/:service_id/config` | 一致的环境服务配置视图与 token |
| POST | `/api/v1/services/:service_id/environment-config?preview=1` | 多目标差异计算和渲染校验，事务回滚 |
| POST | `/api/v1/services/:service_id/environment-config` | 多目标原子保存 |
| GET | `/api/v1/services/:id/revisions?latest=1` | 只读最新版本，旧的历史列表接口保持兼容 |

## 加载优化和保护

- 服务图标从 17px 缩为 14px，底框从 28px 缩为 22px；本地 SVG，无外部图片下载。
- 服务编辑只读最新版本，避免下载所有历史正文。
- 服务页不请求集群工作负载、不逐服务拉取构建摘要、不逐工作流拉取运行历史；初始化必要校验在后台进行，不阻塞服务选择。
- 后台批量请求最多四个并发。切换到相应页面再加载统计、运行资源。
- 修复原“加入环境”始终打开首个环境的问题；服务/环境切换保留用户选择意图，未保存编辑先提示。
- 异步响应检查当前服务/环境；读取失败不生成虚构的 port/replicas/CPU/内存默认值。共享模板读取失败禁止保存。

这些变化减少请求量和等待依赖，不能据此承诺所有网络条件下的固定加载时延。
