# 构建修改记录与 Commit 跳转

## 查看入口

1. 打开项目 → 工作流 → 对应工作流。
2. **执行记录**的“分支 / 最新 Commit”显示这次实际构建的短 Commit 和提交说明。点击蓝色 Commit/说明，在新标签页打开该仓库的提交详情，可查看代码差异。多服务运行会分别显示每个服务的 Commit。
3. 切换到 **修改记录**，找到运行记录并点击“展开本次修改”，查看提交列表、作者、提交时间和变更文件；“在仓库查看完整差异”跳转到比较页面。
4. 在单次运行详情中，也可以直接打开 **代码变更**。构建详情抽屉和交付概览显示相同的 Commit 链接。

列表每页 20 条，只加载摘要；展开后才读取完整修改记录。构建尚在运行时，展开的详情自动更新，结束后停止轮询。保存的修改记录与构建 Job 分开存储，正常清理 Job 不会删掉这些记录。

## 比较规则

- 比较基准是本次构建入队时，同项目、服务、仓库地址、分支的上一次成功构建。失败构建不替代成功基准。
- 基准保存在构建快照中。并行构建、服务后续修改仓库、重试构建，都不会改变已经固定的比较范围。
- 首次构建没有基准，仅展示当前提交，不把整个仓库误报为本次修改。
- 与基准相同的 Commit 明确显示“没有新增提交”。
- 浅克隆、历史改写或取历史超时导致无法比较时，显示“比较历史暂不可用”，不显示成“没有修改”。
- 最多显示 100 条提交、200 个变更文件，并限制采集字节数。超出时显示截断提示，完整内容可到仓库查看。额外拉取历史最多加深 200 层，超时 30 秒；采集失败不会导致已经成功的代码检出失败。

## 生效范围与权限

新版本 API、Worker 和数据库迁移 043 生效后的新构建会采集完整记录。旧构建未保存的提交明细无法凭空补回；页面会明确说明缺少记录。旧记录只要保存了完整 Commit 和仓库快照，且能确定代码源类型，也可生成蓝色 Commit 链接，无需重新构建。代码源类型未保存在旧快照时，会核对当时引用的代码源 ID、项目范围、服务器地址和部署路径；匹配后才生成链接，不使用服务当前仓库替代历史仓库。证据不足时保留普通文本。

自动生成链接支持已配置的 GitLab、GitHub、Gitea、Gitee HTTP(S) 仓库。链接指向构建快照中的仓库，不包含代码源凭据。私有仓库在新标签页中仍使用你自己的 Git 平台登录权限，AxiOps 不把构建 Token 传进浏览器链接。
