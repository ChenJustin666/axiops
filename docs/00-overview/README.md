# 产品总览

## 产品设计

AxiOps 定位为企业级云原生与混合云运维平台，统一承载权限、Kubernetes、资产、CI/CD、监控、日志和受控 AI 运维。目标规模为 100+ 开发人员、约 5000 台主机、首期 10 个 Kubernetes 集群，并按 20-50 个集群扩展。

产品主线是“项目 -> 服务 -> 环境 -> 资源 -> 交付与观测”。用户进入项目后，只能看到被授权的服务、集群、构建、发布、监控和日志。

## 核心需求

- 支持权限中台接入和平台内建用户、部门、角色、菜单、动作与数据范围授权。
- 支持多云、多区域、内网和受限网络统一接入。
- CI/CD 支持构建、制品、发布、审批、回滚、Helm 和通知。
- 监控与日志统一查询，并强制继承项目、服务、环境和集群权限。
- AI 只能在当前用户权限内分析，写操作必须走平台 API、审计和风险控制。

## 技术设计

首期目标进程：

| 服务 | 职责 |
|---|---|
| platform-api | 身份、权限、项目、资源、集群、资产 |
| cicd-api | 服务、构建、流水线、制品、发布、审批 |
| observability-api | 指标、日志、告警、值班、AI 查询 |
| task-worker | 构建同步、通知、采集配置、定时任务 |
| axiops-web | 唯一前端 |

详细拓扑、容量与非功能要求见[总体架构](ARCHITECTURE.md)。

## 实施计划

1. 权限和资源归属闭环。
2. CI/CD 构建、Helm 发布与通知闭环。
3. 监控、日志查询与多区域采集。
4. Kubernetes、资产和前端体验收敛。
5. Agent 与只读 AI 运维。

## 验收标准

- 任一列表、详情、操作都无法绕过数据范围。
- 构建到发布可追溯到提交、制品 digest、操作者和环境。
- 5000 台主机、20-50 集群架构可水平扩展。
- 所有写操作可审计，关键功能有自动化测试和完成记录。
