# CI/CD 服务向导与发布草稿工作记录

日期：2026-09-07

## 目标

按 Zadig 的服务模型，把 K8s YAML、Helm Chart 和主机应用统一成“项目 -> 服务 -> 环境 -> 工作流”的交付链路。服务定义只保存一次，环境保存目标、变量和发布覆盖；构建产物通过 digest 在多个环境之间晋级。

## 完成内容

- `ServiceCreationWizard.vue` 提供三步向导：选择创建方式、选择代码库/定义或模板、确认构建与工作流初始化。
- 支持手工输入、从平台公共代码源同步和使用模板三种入口；代码源支持 Gitea、GitLab、GitHub、Coding 及内网 HTTP 地址，凭据只引用平台加密记录。
- 代码库同步支持分支、Tag 或 Commit 固定；目录浏览器可以选择 YAML、Chart 或主机定义文件，保存时生成不可变服务 Revision。
- K8s YAML 支持多目录批量同步；每个服务目录生成独立服务和 Revision，失败项单独显示，不掩盖已成功服务。
- Helm 服务保存 Chart、values 和 Release 元数据，环境覆盖只记录 values 差异；主机服务保存制品地址、checksum、主机组和 Agent 发布参数。
- 自动识别语言、框架、Dockerfile、镜像字段并填充默认构建配置；用户可以在构建配置和工作流编排中继续修改。
- 初始化工作流可选择构建、自动化测试、审批和部署节点；部署节点按项目类型生成 `yaml_deploy`、`helm_deploy` 或 `host_deploy`。
- `ReleaseDraftDrawer.vue` 提供三步发布草稿：选择工作流/服务/Revision、选择已经验证的环境目标、查看 Diff 并确认创建运行。
- 发布草稿支持多服务、多环境、Revision、滚动/金丝雀/蓝绿、并行/顺序执行和健康检查超时；同一 digest 可晋级多个环境，不重复构建。
- 生产环境或显式审批环境必须包含人工审批节点；每个环境目标在运行时生成独立部署 Job、日志和审批状态。
- 运行详情展示构建、测试、审批、部署、Commit、镜像 Digest、资源变更和错误日志，可从 Commit 跳转代码源。

## 数据与权限边界

- 服务 Revision、环境服务覆盖和运行快照分离保存，修改环境副本数或变量不会改写服务基线。
- 项目、服务、环境、集群、工作流和操作均复用后端授权校验；没有范围权限的资源不会进入列表，前端隐藏按钮不作为安全边界。
- 发布批次只写运行快照，不修改工作流定义；取消或失败不会覆盖已经成功的其他目标。
- 本轮没有新增 SQL，现有迁移版本保持 `028_access_department_workflow_scope.sql`。

## 验收场景

1. 创建一个 K8s YAML 项目，从公共 Gitea 仓库同步两个服务目录，确认每个服务有独立 Revision。
2. 创建只含测试和生产的环境组合，分别绑定测试/生产集群和 Namespace；项目中不显示未配置的开发或预发布环境。
3. 为同一个服务执行一次构建，在测试环境发布后把相同 digest 晋级到生产；确认生产运行先停在审批节点。
4. 修改测试环境副本数和变量，确认页面显示环境覆盖 Diff，服务基线 Revision 不变。
5. 选择多个服务和多个环境创建发布批次，确认运行详情按目标显示独立 Job、日志和状态。

## 已知限制

测试节点当前在 Worker 中使用可替换的 `TestCommandRunner`，本地默认实现为宿主机 Shell，便于联调。生产必须替换为受限 Kubernetes Job 或专用 Agent，并通过网络、资源、凭据和工作目录策略隔离。该限制不影响服务向导和发布草稿的前端验证，但在生产上线前必须完成。
