## 实现与边界

| 项目 | 本轮行为 |
| --- | --- |
| 取消工作流 | 停止待执行节点，取消运行中的构建/测试 Job，保存日志后收敛；重复取消可重复调用。已提交的 YAML/Helm/主机部署等待原操作状态，不删除服务、不额外触发回滚。Helm 自身已有 atomic 行为保持。 |
| 一个节点失败 | 工作流先进入停止阶段，取消其他构建、停止后续节点、观察已提交部署，最后标记失败，避免剩余 Job 脱离调度。 |
| Worker 重启 | 工作流 ID + 节点 + 明确重试轮次生成持久标识；租约重领不改变标识。提交结果不确定时保留运行状态，先查找原 BuildRun；取消与持久化构建入队在数据库中串行校验。 |
| 租约与调度 | 同步执行续租并感知取消；过期 Worker 不能完成任务。状态回写核对对应 provider ID，避免旧轮次覆盖重试。轮询游标绕过长期运行记录；一个运行错误不阻止其他运行。默认 4 个调度循环（Worker.Concurrency，可设 1–32），数据库租约去重；实际构建并发仍使用原平台限额。 |
| 自动重试 | 仅构建节点支持，10 秒起退避，上限 160 秒。复用原配置快照与完整 Commit，生成新构建记录/镜像 tag，保留失败原因和旧日志链接。未取得完整 Commit、明确超时、权限错误不盲目重试。租约 attempt 与 retry_count 分开。 |
| 超时 | 同步节点由 context 限时；构建/测试节点超时请求取消 Job，等待停止再终结。构建任务和部署 provider 原有 deadline 保留；不是所有 provider 的超时恢复已完全统一。 |
| 测试隔离 | 生产 Worker 改用独立 Kubernetes Job：选择测试镜像、命令和仓库相对目录；独立 emptyDir 检出，禁止工作目录越界，不挂 Worker 文件系统、不传 Kubernetes token、不启用 privileged。复用构建队列、资源限制、日志、取消和清理。依赖本服务成功构建时使用该构建的仓库快照及实际 Commit；并行无依赖构建不影响代码选择。 |
| 测试日志 | 成败均通过现有 Job 日志保存、展示；实际运行页和抽屉都识别 test 的 build provider ID。重试等待时清空旧容器输出，保留工作流诊断。 |
| 旧发布接口 | `/api/v1/releases` 及旧详情/审批/回滚返回 HTTP 410，不读写旧发布记录。实际工作流与 deployment-snapshots 回滚不受影响，避免“请求成功但无部署”与跨项目旧接口读取。 |
| 发布文案 | 删除 ReleaseDraftDrawer“不重新构建、同一产物”承诺。当前普通发布执行工作流全部节点；固定产物晋级尚未接通。 |
| 模板创建 | 默认一个服务，可展开逐节点绑定；纯通知模板不要求服务。服务版本缺失会阻止部署模板创建。 |
| 运行页 | 原无行为的“变更”改为“本次配置”，显示本次节点绑定的服务版本/分支/执行记录，不展示凭据或内部配置正文。它不是完整历史差异审计。 |
| 主机目标 | 运行提交时冻结主机配置及在线 Agent 列表；执行时重新核对成员，新增成员不会自动进入本次发布，原目标离线或移组时拒绝替换。 |
| 纯构建入口 | 修复没有环境时执行按钮仍被禁用的问题；不再统一显示“构建并部署”。 |

## 使用步骤

1. 数据库恢复后先应用迁移 041，启动本轮 API/Worker（下面有命令）。前端开发模式刷新页面即可加载修改；生产前端需要使用新打包产物。
2. 打开项目 → 工作流 → 编排。构建节点按需要设置“失败自动重试次数”；部署节点不开放自动重试。
3. 测试节点选择服务、测试镜像、命令。Java 示例：镜像 `maven:3.9-eclipse-temurin-17`，命令 `mvn -B test`；多模块目录填仓库内相对路径。测试应依赖相应构建节点以固定相同代码版本。旧测试节点若没有镜像，须补齐后保存。
4. 执行后点击构建/测试节点查看容器输出。重试记录在运行抽屉中可展开，旧构建 ID 对应的日志仍保留。
5. 在运行抽屉取消。页面进入停止阶段；底层执行未确认退出时不会提前显示取消完成。取消不会删除已经部署的服务。
6. 从模板新建多服务工作流时，展开“按节点选择服务”；核对构建与部署节点的服务对应关系及固定目标环境。
7. 运行页“本次配置”查看本次使用的配置版本。修改服务配置后需要新部署才能生效。

## 启用顺序

当前数据库 TCP 连接超时；只有 3006 监听，8090/8091 未监听。未启动 Worker，未执行任何业务构建、发布、通知或自动清理。

迁移文件：`migrations/041_workflow_task_retry.sql`，增加 retry_count、next_retry_at、retry_history。旧数据库未应用迁移时，新 API/Worker 会拒绝启动。当前 configs/cicd-api.yaml 设置 AutoApply=false，不能只重启跳过迁移。

数据库连接恢复后，在仓库根目录执行：

```powershell
go run ./cmd/axiops-migrate -f configs/cicd-api.yaml
go run ./cmd/axiops-migrate -f configs/cicd-api.yaml -check-only
powershell -NoProfile -File scripts/restart-cicd-api.ps1 -BinaryName axiops-cicd-api-delivery-fixes.exe
```

启动平台 API 以恢复登录，并按现有运维方式把 Worker 可执行文件切换为 `bin/axiops-workflow-worker-delivery-fixes.exe`。Worker 启动会消费真实待执行任务，先核对队列。不要因旧二进制存在而继续启动旧 Worker。

本轮 git-clone 脚本嵌入 Worker，记录完整 Commit 到容器 termination message；不要求重新打包平台 builder 镜像。测试镜像须支持 `/bin/sh`，私有测试镜像的独立拉取凭据选择尚未接通。
