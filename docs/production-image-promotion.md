# 选择镜像发布与构建部署

2026-10-16 更新。本页取代早期“必须配置来源、人工验收后才能发布”的使用说明。

参考云效 Flow 的构建产物选择和 Kubernetes 部署方式，日常发布使用下面两条路径：

| 场景 | 操作 | 是否构建 |
| --- | --- | --- |
| 测试环境发布新代码 | 选择服务、分支，构建并部署 | 是 |
| 将已有镜像发布到生产 | 选择服务、镜像，发布 | 否 |
| 生产需要发布尚未构建的新代码，或项目只有一个环境 | 切换“构建并部署”，选择分支并执行 | 是 |

## 第一次准备

1. 创建实际需要的环境，各自绑定集群与 Namespace。可以同集群不同 Namespace。工作流固定绑定目标环境，执行时显示目标。
2. 在“服务与配置”切到目标环境，为每个服务保存该环境自己的 YAML 与配套配置。核对副本、CPU/内存、端口、启动参数、域名、Nacos namespace、数据库地址和 Secret/ConfigMap/PVC 引用。
3. 配置服务构建方式和工作流。复用镜像需要成功构建记录及镜像摘要。构建并部署需要相应服务的构建节点和 YAML 部署节点。

生产已有审批设置继续生效；本轮不增加新的审批流程。已有工作流中的测试、其他类型部署节点不会被悄悄跳过，不支持复用的编排会明确提示。

## 已有镜像发布

1. 打开目标生产工作流，点击“执行”。默认“使用已有镜像”，默认选择一个服务。
2. 日常直接选择镜像。“镜像来源”收在右侧小型“高级”入口中，默认测试环境；需要时展开，切换其他环境或“全部来源”。收起不会重置筛选或已选镜像，无需先保存发布策略。无测试环境时也可以选择镜像。
3. 在服务下方直接选择镜像版本，查看标签、构建时间、分支、Commit 和部署结果。可展开镜像下拉查看更多版本。
4. 系统优先选择该来源已成功部署过的最近构建；没有部署记录时选择最新成功构建。构建成功、部署成功均不代表业务功能测试通过，业务测试仍由团队完成。
5. 选择后自动检查目标环境配置。无阻塞时直接点击“发布”或“提交发布”。配置差异与完整 YAML 可展开查看，不需要额外刷新或勾选确认。
6. 在运行详情查看执行人、源构建、日志、耗时与就绪结果。发布固定使用所选镜像的 `sha256` 摘要；生产使用自己的配置，不会复制测试环境的配置。

镜像标签含 `test` 也可以用于生产。标签表示构建来源，不表示部署目标；复用发布不会为生产重建一份镜像。实际版本以摘要为准。

“本次构建变更”链接是该构建记录保存的代码比较，不一定是与当前生产版本的比较。Commit 与代码变更链接在存在有效 HTTP(S) 地址时提供，没有地址时保留提交号。

刷新镜像保留所选服务顺序和版本。若版本已不可用会阻止提交，不自动替换成另一份镜像。多服务每个服务选一份镜像，支持上移/下移，全部检查通过后创建一次运行。

## 构建并部署

1. 测试和生产执行窗口采用相同布局：目标环境、部署目标、发布服务、发布方式、各服务的分支或镜像。测试默认“构建并部署”，生产默认“使用已有镜像”。
2. 在生产窗口切到“构建并部署”后直接显示分支配置，核对服务、分支和目标环境后执行。可切回“使用已有镜像”，保留所选服务及顺序，不触发发布。未选服务时先选服务再继续。
3. 目标仍是当前生产环境，不会自动跳到测试环境。只有一个环境也支持这条路径。
4. 使用本次构建生成的镜像与提交时冻结的目标环境配置。多服务沿用全部构建成功后按所选顺序提交部署的策略。

日常生产优先复用经过团队验证的镜像；需要新代码时主动选择构建方式。

测试执行默认只选一个服务，服务下拉切换选择，选中后才展开对应配置。支持多服务的工作流可多选并上移/下移。构建窗口“高级”中保留“按工作流配置执行”，展开前也会明确展示当前全部执行范围；自定义工作流不支持替换服务时仍执行原编排。

## 常见提示

- **请先保存生产环境配置**：该服务尚无目标环境配置。点击提示旁“配置目标环境”直接进入对应服务与环境，保存后重新执行。平台不会自动把测试配置当成生产配置。
- **此来源暂无成功构建的镜像**：切换来源/全部来源，或选择构建并部署。
- **版本、配置或环境已变化**：重新检查后再提交，不能使用旧的预检结果。
- **已有未结束的发布或回滚**：处理或等待当前运行完成，再次检查。
- **提交结果尚未确认**：点击“核对提交结果”，使用原请求查证，避免重复创建发布。

历史 `verified_image` 运行仍校验原验收记录及撤销状态；新的普通镜像发布使用 `selected_image`，不会伪造测试验收记录。

参考：[云效 Kubernetes 镜像升级](https://help.aliyun.com/zh/yunxiao/user-guide/kubernetes-image-upgrade)。这是借鉴其构建与部署分离的设计，不代表平台已覆盖云效所有能力。
