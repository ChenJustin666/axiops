# 删除项目

## 操作步骤

1. 打开“持续交付 → 项目交付”，点击项目卡片右上角菜单。
2. 选择“删除项目”，查看未结束任务与将清除的数据数量。默认彻底删除，不保留项目配置和执行历史。
3. 可删除时，手动输入完整项目名称，必须与提示完全一致，包含大小写和空格。
4. 点击红色“彻底删除”。成功后列表自动更新，无需手动刷新，可以使用原名称与编码重新创建项目。

若需要保留配置、执行记录和日志，先勾选“保留配置与执行历史”，再输入名称并点击“删除并保留历史”。切换删除方式会清空名称确认，避免误操作。

只有拥有该项目删除权限的账号会看到删除入口，后端会再次校验权限与名称。检查期间、名称不匹配时不能提交；执行删除期间不能重复提交或关闭确认框。

## 哪些情况会阻止删除

已成功、失败、超时或取消的历史执行记录不会阻止删除。未完成初始化的项目同样可以删除。

排队、运行中、取消中、等待审批及尚未确认结束的任务会阻止删除，构建资源回收未结束或构建命令正在处理时也会阻止删除。确认框显示具体任务数量。先等待任务结束，或在执行记录中取消，确认取消及资源回收完成后再删除。仅发出取消请求不等于任务已经结束。

不需要先删除构建、工作流或部署历史，也不需要清理数据库关联表。

## 删除后的行为

默认彻底删除：在一个数据库事务中清除项目自身的服务、环境、版本、变量、成员、权限绑定、工作流、构建和部署记录、日志、通知订阅与编号序列，最后删除项目。任何一步失败都整体回滚。其他项目、平台全局资产和审计记录保留。

可选保留历史：项目状态改为 `deleted`，保留项目配置与记录，停止修改和执行。项目列表的“状态”筛选中选择“已删除”，点击项目可进入只读历史页面。可查看工作流详情、任务日志和构建记录；不提供执行、审批、取消或编辑操作。

两种方式都会释放项目编码；仍在使用或停用的项目编码不能重复。保留历史的旧项目保留原编码与独立 ID，不会关联到新建的同编码项目。

清理之前已软删除的项目：状态筛选“已删除” → 项目卡片菜单 → “彻底删除” → 输入完整名称确认。此操作不可恢复，没有恢复项目入口。

## 删除边界

不会调用 Kubernetes、主机或仓库接口，不会删除集群、Namespace、PVC 数据、运行中的应用、Git 仓库或镜像。需要下线实际应用时，应先完成对应环境的下线操作，再删除项目。

确认框的检查只是预览，真正提交时后端会重新检查未结束任务并严格核对项目名称；期间新增了任务，或项目名称已改变，删除会被拒绝。提交任务与删除使用同一项目状态锁，防止删除后启动新的构建、工作流或回滚。
