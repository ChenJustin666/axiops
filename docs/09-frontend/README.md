# 前端模块

## 产品设计

保留单一 axiops-web，面向运维高频操作设计紧凑、可扫描的工作台。全局上下文统一为项目、环境、集群、Namespace 和时间范围。

## 需求

- 菜单和按钮按权限渲染，但后端仍负责安全校验。
- CI/CD 展示阶段、实时日志、失败原因、制品和发布状态。
- 监控支持总览、资源详情、时间范围和发布标记。
- 日志支持搜索、字段、上下文、实时流和保存查询。
- 页面在常用桌面和移动尺寸不重叠、不溢出。

## 技术设计

复用现有 Vue 技术栈和组件基础，逐模块替换旧页面。权限、项目和环境上下文由统一 store 管理；API 错误码统一处理 401/403、超时与重试。

当前 AxiOps 登录已直接使用 `platform-api` 的 `axiops` 身份库和新 JWT。新路由不再调用旧
`/portal/v1` 登录、用户或平台上下文接口；历史账号迁移仍按[身份收敛方案](../01-authorization/IDENTITY_MIGRATION.md)
执行，但不再阻塞新管理员账号登录验收。

## 实施计划

1. 完成旧/新身份收敛和统一认证会话。
2. 统一品牌、导航、上下文和权限 store。
3. 完成用户、角色、资源范围配置页面。
4. 完成 CI/CD 列表、详情、日志和发布页面。
5. 完成监控与日志工作台。
6. 收敛 Kubernetes 和资产页面。

权限前端是本次重构的必需交付，不只保留后端接口。页面必须覆盖用户/部门、角色权限、菜单可见性和资源范围绑定，并能按项目、服务、环境、集群、构建任务、工作流限制查看或操作能力。

## 完成进度

### 集群管理页面（2026-08-20）

路由为 `/clusters/management`，由 `cluster:view` 控制可见性。管理员可以粘贴专用 kubeconfig 接入测试集群，页面会自动读取 API Server，保存后只显示脱敏元数据和连接指标。编辑不会回显 kubeconfig；更新 kubeconfig 后服务端会重新探测连接。删除操作由后端检查环境和发布引用，已引用集群会拒绝删除。

权限中心的“资源授权”支持选择“集群”范围，把只读或运维角色绑定到单个集群；页面授权只是入口过滤，后端仍逐次校验。

- 已完成：权限中心覆盖用户、直属部门、角色权限矩阵、显式拒绝、菜单选择和六类资源范围授权。

## 验收标准

- 不同角色只能看到可用入口和操作。
- 构建过程状态清晰，失败原因和通知结果可见。
- Playwright 覆盖核心流程和桌面/移动布局。
