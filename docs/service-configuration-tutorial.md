# 服务配置与部署操作教程

每个环境维护自己的完整服务 YAML、参数和配套配置。模板只用于开始时创建副本，修改模板库不会自动影响已经创建的服务。保存配置不会自动部署，必须在工作流中明确发布。

## 推荐入口：现有模板和标准 YAML

优先从模板库选择已有基础模板，填写当前环境参数后创建。在“服务配置”选择服务和目标环境，直接修改整份 YAML；需要增加 deployment.yaml、service.yaml、ConfigMap、Ingress、PVC 等文件时，右键左侧服务目录选择“新建 YAML”。所有文件在同一编辑区以 `---` 分隔，点击文件名会定位到对应资源。

例如新建 `configmap.yaml`：

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: {{.Service}}-config
data:
  application.yaml: |
    server:
      port: 8080
```

手写 ConfigMap 后仍需在 Deployment 的 `volumes` / `volumeMounts` 中引用；也可以使用“配套配置 → 配置文件”生成资源和挂载。已有资源可直接在 YAML 中引用。密码通过目标环境“配套配置 → 密码与凭据”管理；普通 YAML 保存链不接收 Secret 正文，Base64 也不属于加密。

## 一、先建环境，再配置服务

1. 初始化顺序是环境 → 服务 → 构建 → 工作流。先创建测试环境，绑定集群和 Namespace；不选择其他环境时只创建一个测试环境。
2. **模板方式**：服务目录顶部点击“模板”，选择目标环境和模板卡片，点击“下一步”，在同一个加宽、加高的弹窗内填写服务名称和参数。模板版本与命名空间显示在表单上方。参数来自选中的模板；Nacos 模板显示 Nacos 地址/Namespace，普通模板无需填写 Nacos。Env/JVM 等参数默认折叠，可按需展开。
3. Deployment、Service 使用模板现有内容。Env / JVM、模板健康检查、其他模板参数分别折叠；只有含监控参数时才显示“模板健康检查与监控”。模板已有标准健康检查参数或原生探针时，不再显示可选探针入口。TCP 不要求 HTTP 路径，健康检查默认关闭。展开可选资源，点击“+ 路由 Ingress”等按钮，填写后点击“完成添加”；完成项显示摘要，可编辑或删除。可以添加多种配置，每次只展开一项表单；先完成或取消当前项，再添加下一项。复杂调度、钩子或其他资源可展开“高级：编辑模板 YAML”，内部变量元数据注释不显示，但保存时保留。
4. 完成添加、编辑或删除可选资源后，自动请求后端生成“最终 YAML 预览”，包含 Ingress、PVC、ConfigMap 及 Deployment 中的挂载、Secret 引用；不会保存或部署。引用已有 PVC、ConfigMap、Secret 时展示引用，不重复创建资源，也不展示密码正文。预览中的模板变量已替换，Image 是校验占位镜像，真实发布时使用工作流镜像。也可点击“预览完整配置”；修改参数、模板正文或目标环境后旧预览失效，需要重新预览。确认无误后点击底部“创建服务”，校验并确认保存。服务目录、首次版本和所选环境配置一起提交；校验失败不会留下半个服务。创建后自动显示刚保存的环境配置。“上一步”返回模板选择，点回同一模板再点“下一步”会保留当前草稿；改选其他模板或退出时，有未保存修改会要求确认放弃。
5. **手动方式**：点击“手动”创建目录，选择环境，在空白编辑器粘贴原生 YAML。不会自动生成模板、CPU/内存参数或替换你写的资源。也支持 `{{.Service}}`、`{{.Image}}`、`{{.Namespace}}` 等系统变量，以及 `$Service$` 等已有写法；不需要手工建立这些系统变量。`Image` 在保存校验时使用占位镜像，部署时注入构建/晋级镜像。自定义占位符则必须填写实际参数。
6. 日常修改只需选择服务和环境，解锁编辑 YAML 或参数，点击“保存环境配置”，核对预览后保存。未保存修改在切换环境/服务前会提示。
7. 一个月后增加生产环境：先在“环境”新建并绑定生产集群/Namespace；选择已有服务并切换到生产，点击“配置此环境”（手动服务可直接写 YAML）。选择模板或“参考测试环境的完整 YAML”，修改生产副本、内存、域名、配置中心等差异，核对后保存。新环境不会自动复制测试凭据、配套路由和存储；手写在 YAML 中的引用需要自己核对。无需额外操作“加入环境”。

Secret 正文仍使用“配套配置 → 密码与凭据”安全创建，不粘贴到普通 YAML 保存链；原生 YAML 可以引用已有 Secret。

## 二、配置普通文件

选择服务和目标环境，在“配套配置 → 配置文件”中添加文件：

- 填写标识、ConfigMap 键和容器内完整挂载路径，例如 `/app/config/application.yml`。
- 直接输入内容，或选择已有 ConfigMap。内容最多 256 KiB。
- 点击抽屉底部“预览与保存”，生成的 YAML 会显示 ConfigMap、挂载和配置哈希；确认保存不会部署。

普通文件内容存入配置记录并生成 ConfigMap。修改后需要再次保存并提交部署，Pod 模板哈希变化会触发工作负载滚动更新。

## 三、配置账号、密码和敏感文件

不要把密码写进 YAML、变量或 Dockerfile：

1. 选择服务和目标环境，点击编辑区顶部“配套配置”，进入“密码与凭据 → 新建多键 Secret”。空白服务先保存 YAML，才能为工作负载添加挂载。
2. 默认“多个键值”，用“添加键值”填写任意键，例如 `username`、`password`、`SK`、`API_TOKEN`、`tls.key`。单行内容使用密钥输入，多行内容选择“多行 / 文件”；每组最多 30 个键、内容合计最多 512 KiB，按原文加密保存。
3. 每个键独立选择环境变量或文件挂载。例如 `username → DB_USERNAME`、`password → DB_PASSWORD`、`tls.key → /app/secrets/private-key.pem`。也保留单个密钥、账号密码、敏感文件的快捷模式；“引用已有凭据 / Secret”可以绑定已创建资源。
4. 填写注入环境变量名（例如 `API_TOKEN`、`DB_PASSWORD`），或填写文件完整挂载路径（例如 `/app/secrets/private-key.pem`），两者选一。系统在部署清单中自动生成 `secretKeyRef`，或 `volumes` / `volumeMounts`，不需要再手写到 deployment.yaml；同一变量或挂载路径不要两处重复配置。仅创建凭据不会自动注入。
5. 点击“预览与保存”，核对服务、环境和命名空间，然后“保存当前环境”。凭据正文不进入普通 YAML、配置差异或工作流配置快照；凭据读取接口不返回已保存正文。

例如测试环境配置两个密钥：新建多键 Secret，第一行键名 `SK`、注入变量 `API_SK`；第二行键名 `token`、注入变量 `API_TOKEN`，分别填写内容。生产环境独立创建生产凭据，不复制测试密钥。应用必须自行读取该环境变量或挂载文件。

多键组点击“编辑键值与引用”：已保存正文不回显，原键内容留空表示保留；填写新内容表示替换，“添加键值”增加字段，“移除此键”删除该字段，改键名需重新填写内容。系统从服务端保留未改的隐藏值，创建独立加密版本；旧版本仍可供已有 Pod 和历史配置引用。修改期间原凭据被别人更新时会拒绝过期保存，请重新打开核对。

旧单条引用点击“更换凭据”时必须填写新内容。所有修改只改变当前环境草稿，还需预览、保存并发布；其他服务和环境不自动变化。取消或切换清空输入正文，并保护未保存草稿。凭据先独立保存到凭据库，取消环境草稿不会删除已创建的凭据。

发布阶段在目标命名空间准备受本服务管理的 Secret。新凭据使用独立 Secret 名称，旧 Secret 保留，避免覆盖旧 Pod 和历史版本的引用；目前不会自动清理旧 Secret。已有同名但归属不明的 Secret 会拒绝覆盖。平台加密存储凭据，集群 Secret 的访问权限和静态加密由 Kubernetes 配置决定。应用主动打印密钥时，平台无法保证容器日志中没有明文。

## 四、配置域名和 HTTPS

在“域名路由”添加域名：

- 域名必须是完整 DNS 名称，例如 `api.example.com`；路径通常为 `/`。
- 选择当前模板中的 Service 和端口，系统会校验端口确实存在。
- 可填写 Ingress Class 和目标命名空间中已有的 TLS Secret。

系统只创建标准 `networking.k8s.io/v1` Ingress。DNS 解析和集群 Ingress Controller 由基础设施负责，配置保存不会替你修改公网 DNS。

## 五、配置 PVC 和现有存储

在“存储”中优先选择已有 PVC，填写其名称和容器挂载目录；引用已有 PVC 时不提交容量或 StorageClass 创建参数。如果新建，填写容量、访问模式和挂载目录；StorageClass 留空使用集群默认类，或填写具体类名。集群没有默认 StorageClass 时，需指定类或由管理员提供可绑定的 PV。

- 解除挂载只解除服务引用，不删除 PVC 和数据。
- 已创建 PVC 的容量、StorageClass 和访问模式不能在此悄悄改写；需要扩容流程或新建一个不同名称的挂载。
- StatefulSet 的每副本 `volumeClaimTemplates` 属于高级模板，不能用单个共享 PVC 设置替代。

## 六、预览、保存和发布

1. 在当前环境编辑 YAML、普通变量和配套配置，这些修改使用同一份环境草稿。
2. 点击“预览与保存”，检查目标工作负载、容器、生成资源和变更列表。
3. 生产环境必须勾选已核对确认框。
4. 点击“保存当前环境”。此操作只写入服务环境配置，不会直接改集群。
5. 在工作流中选择该服务、分支和环境，提交构建并部署。构建产物镜像会在执行阶段注入，服务配置不需要手抄镜像地址。
6. 部署后到环境运行资源查看 Deployment、Pod、Service、Ingress、ConfigMap、PVC 状态；拉取失败、权限失败和探针失败会显示事件和容器日志。

切换环境、服务或离开页面时，如果有未保存修改会先提示。

### 测试配置变更如何同步到生产

1. 在测试环境完成修改并保存，点击“同步配置”，选择生产目标。一次处理一个目标，界面明确显示来源、目标、集群和 Namespace。
2. 默认不选择任何同步内容。“选择需要同步的参数”默认折叠，需要时展开，仅勾选要复制的项，例如服务端口；复制的是来源实际值，未选中的生产副本、内存等参数保留。密码和凭据不能在此复制。
3. 需要更新共享基础版本时选择“更新基础配置版本”。已有环境独立 YAML 与升级冲突时会阻止保存，请在目标环境比较和处理。
4. 修改了 YAML 结构时，选择“使用来源 YAML 编辑目标草稿”。这是完整 YAML 替换，必须在草稿里保留生产独有资源，并修改测试域名、Nacos 地址/Namespace、Secret/PVC 名称和启动参数。系统不会推测这些硬编码字段的生产值。目标“配套配置”中的凭据、文件、路由和存储设置不随此操作复制；正文中手写的资源及引用仍需核对。
5. 点击“查看差异”，核对变量、保存前后 YAML 和目标渲染结果。完整 YAML 需勾选已核对；生产环境还需确认生产目标，再“保存到目标环境”。所有选中修改一次保存，不会出现逐个目标保存导致部分成功的情况。
6. 修改目标或草稿会立即撤销旧预览与确认。来源、目标参数或集群/Namespace 在后台发生更新时，服务端拒绝过期请求；重新加载并预览后再保存。结果无法确认时先重新加载核对，不要连续重复提交。

配置预览校验语法、变量、命名空间和资源约束，不能替代真实集群检查或业务验证。建议保留 `{{.Namespace}}`、`{{.EnvName}}` 等环境占位符，并通过目标环境变量或“配套配置”管理地址与凭据，减少正文硬编码。

### 测试通过后发布到生产是否需要重新构建

1. 先确认已保存该服务的生产环境配置，核对生产自己的 YAML、运行参数、域名与凭据。
2. 打开绑定生产目标的部署工作流，点击执行，默认使用“指定服务”。在“镜像来源”选择“使用已有成功镜像（不构建）”，再选择测试通过的成功构建。
3. 发布使用固定镜像摘要和生产环境配置，不复制测试环境配置。没有可复用成功镜像时会阻止执行，不会悄悄重新构建。代码、Dockerfile 或编译参数改变时应重新构建并测试。
4. 仅修改当前环境配置时，可以沿用其已部署镜像走配置发布；首次部署没有已部署镜像时，使用成功构建镜像或重新构建。

配置同步与镜像发布是两个独立动作，创建或保存配置不触发工作流。既有工作流的权限、目标校验和审批策略继续生效。

## 七、常见问题

- **提示 `yaml contains undefined variables`**：先在共享模板保存变量默认值，或在目标环境打开“覆盖”并填写值。`Image` 由部署时构建产物注入，不要求手工填写。
- **提示无法读取凭据**：确认凭据属于当前项目且当前账号有查看权限；不要把密码改写到 YAML。
- **ImagePullBackOff**：检查镜像仓库路径、推送凭据和目标环境的拉取 Secret；构建成功不代表节点一定有拉取权限。
- **BuildKit `no space left on device`**：清理构建节点磁盘和 inode，并检查 rootless 所需的 `user.max_user_namespaces`；这是节点资源问题，不是 Dockerfile 语法问题。
- **Dockerfile 为空**：单模块 Dockerfile 放仓库根目录；多模块项目在服务模块目录放 Dockerfile，并在构建配置中选择对应上下文和文件路径。

## 验证范围

相关 Go 测试覆盖原子创建、预览回滚、手动空白首次保存、系统占位符、命名空间错误回滚、目标参数保留、过期来源拒绝，以及 YAML 与参数一次提交。前端测试覆盖可选能力、手写资源保留、不同服务/环境隔离和初始化顺序。浏览器使用真实登录和健康检查，业务保存使用隔离模拟；未执行真实生产集群部署。
