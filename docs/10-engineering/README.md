# 工程规范

## 产品设计

工程体系服务于四个目标进程和一个前端，采用渐进迁移，不一次性推倒旧服务。

## 开发要求

- Go 使用标准格式化、清晰分层和 context 传递。
- Handler 只处理协议，Logic 负责编排与鉴权，Repository 只处理数据。
- 配置使用 YAML 模板与环境变量覆盖，密钥不得写入仓库。
- API 使用统一响应、错误码、request ID、结构化日志和健康检查。
- 数据库迁移只前进，不手工修改生产表。

## 测试与交付

每个功能必须包含：

1. 需求或设计更新。
2. 代码和迁移。
3. Logic 单元测试与接口测试。
4. 必要的前端或集成验证。
5. 所属模块进度记录。

## 工作流

1. 修改前检查工作区和调用链。
2. 实现后运行格式化、目标测试和编译。
3. 涉及页面时运行 Playwright 截图检查。
4. 测试受环境阻塞时记录原因，不能写成通过。

本地旧服务启动与代码学习说明见[本地开发指南](LOCAL_DEVELOPMENT.md)，凭据加密和密钥注入要求见[凭据存储约束](CREDENTIALS.md)。该文档包含过渡期旧服务，目标运行服务以[产品总览](../00-overview/README.md)为准。
