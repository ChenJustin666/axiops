# 平台权限架构与本批交付

更新：2026-10-16。本文区分基础修复和模块接入要求，不能据此认为全部模块已经统一鉴权。

最新增量：已实现 YAML 工作负载 `deployment:restart` 独立授权，要求同一目标的环境/服务/工作流查看权限，提交和执行前重新校验。环境资源写入、回滚、镜像来源环境和取消任务补齐环境编码/集群及归属校验。操作、测试和运行边界见 [WORKLOAD_RESTART_2026-10-16.md](WORKLOAD_RESTART_2026-10-16.md)。旧监控/日志资源范围接入仍待实施。

## 统一规则

统一登录账号，采用「角色定义操作，授权绑定资源范围」：账号/部门 → 角色 → 功能操作 → 目标资源。菜单只控制入口，后端决定请求是否允许。项目管理员不自动成为集群管理员，查看不包含修改、导出、重启或生产操作。

例如：给开发者分配「项目 A 开发者」并限定测试环境，可以编辑获授权配置、执行测试工作流；发布生产、修改集群接入、读取凭据明文均需独立授权。环境编码必须与资源所属项目和环境 ID 一起核对，不可仅凭 `qa` 或 `prod` 匹配跨项目资源。

默认拒绝；匹配的显式 deny 优先于所有 allow；多个 allow 可以合并。环境条件与资源范围取交集。旧 `read` 仅兼容 `view`，`write` 仅兼容创建/修改/删除，不包含重启、部署、回滚、审批、生产管理等操作。

## 各模块如何适配

以下是接入契约，并非已上线功能清单。操作名称需在实际接入时收口到共同的权限目录。

| 模块 | 分开的操作 | 范围与约束 |
| --- | --- | --- |
| CI/CD | 查看、配置、执行、取消、部署、回滚、生产管理 | 项目/服务/工作流/环境；服务端解析实际归属和绑定目标 |
| 监控 | 查看指标/看板、导出、编辑规则/告警配置 | 项目或集群、环境对应的命名空间；不能借任意查询绕过资源过滤 |
| 日志 | 查看/检索、导出、管理采集配置 | 授权集群/环境/服务；搜索、计数、下载、实时流采用同一边界 |
| AI | 调用分析、读取来源、执行工具 | 分别校验调用、每个检索来源和工具目标；AI 不获得额外权限 |
| 集群 | 查看、接入、编辑、删除、测试连接 | 平台或具体集群；业务项目权限不推导为整个集群管理权限 |
| 环境运行资源 | 查看状态/事件、容器日志、滚动重启、扩缩容、终端 | 环境解析集群与 Namespace；写操作单独授权，终端不能由日志查看权限推导 |
| 凭据与 Secret | 查看元信息、创建/更新、引用/使用 | 平台共享与项目私有分开；引用不代表读取明文；预览、日志、AI 上下文脱敏 |
| 版本/缓存/Agent/通知 | 查看、管理、使用/执行 | 复用项目/服务范围；通知接收者和执行人身份固定，外部消息只含允许公开的摘要 |

AI 示例：用户能发起故障分析但无生产日志权限时，不向模型提供生产日志；用户只能管理测试服务时，AI 不能代其重启生产 Pod。工具执行前重新授权，不能信任提示词自称的身份或范围。

后台任务需固定发起人和目标快照，区分平台调度身份与用户操作。执行、重试和恢复不能把受限请求提升为 Worker 全局权限。流式日志、终端、长时 AI 任务也需要到期与撤销机制。

## 后端接入标准

1. 从验证后的会话获取操作者，通过服务端资源记录解析项目/服务/环境/集群归属，不直接信任客户端传入的 scope。
2. 对具体动作鉴权；列表、分页总数、搜索、详情、事件、日志、导出都要检查，不能只隐藏菜单或按钮。
3. 列表在数据库/数据源层过滤后分页。完整表达范围交集与 deny，不能用“拥有任意一条权限”替代当前目标授权。
4. 审计保存操作者、目标身份、环境/集群/Namespace、动作、操作 ID、结果和时间，不记录密码或令牌。异步操作区分已接收、已提交、已完成。
5. Kubernetes 服务账号权限作为第二层边界。平台获得 kubeconfig 不代表用户获得整个集群权限。

## 本批已完成

- 前端判断与 `internal/shared/authz.Authorize` 对齐。漏传目标不能把局部授权当成全局授权；未知范围、无效 ID、环境不匹配均不授权。
- 集群管理按当前行 ID 判断编辑、删除、测试连接；查看集群不再显示测试连接操作。
- 服务配置、环境解绑、工作流编辑与运行详情传入对应环境 ID/编码。
- 权限缓存随退出、token/账号更换、角色快照变化失效。角色更新替换旧快照，不通过合并保留已撤销角色。
- 丢弃旧账号延迟返回的权限请求；刷新失败清空旧权限并允许重试；并发读取合并，下一次读取距上次成功超过 60 秒重新请求。这不是后台实时推送，后端仍逐次按数据库当前权限判断。
- 权限中心保存角色/资源绑定后刷新当前策略。角色支持 `cluster:test`、`environment:manage_production` 和独立 `deployment:restart`；重启前后端与受控验收已完成，运行中的本地后端尚未更新。
- Go/TypeScript 共用 30 组规则用例，覆盖跨项目、服务/环境范围、显式拒绝、监控与日志分离、日志导出、AI 与来源读取分离。这是规则测试，不替代模块 HTTP 验收。

## 当前边界与迁移顺序

目前并存两条历史实现：新版平台/CI/CD 使用 `internal/shared/authz`，从用户角色、项目成员、用户/部门资源绑定读取当前策略；旧模块使用 `application/portal-rpc/internal/authz` 的 Casbin API 权限和资源范围检查。它们没有因本批改动自动同步角色。监控、日志需要按实际入口逐个适配和验收；本次未找到实际 AI 后端入口，AI 权限仍为后续接入契约。

后续已补齐旧登录链路的当前账号/角色查询：普通 JWT、刷新令牌、系统 Token 不再继承已撤销角色或缓存中的失效状态。账号停用/删除、要求重置密码、角色/绑定软删除、Token 停用/删除/到期均检查当前数据库记录；不影响已有 Redis 会话和 Casbin API 保护。它不是新旧资源范围适配；具体入口、资源映射缺口、原始日志查询和长连接限制见 [旧模块接入核对](LEGACY_MODULE_AUTHORIZATION_2026-10-16.md)。

不能直接复制旧角色 ID、放开通配权限或只增加前端选项来宣称完成统一。保留旧保护，建立身份/动作映射，再将接口收口到共同契约；验证两个入口不能互相绕过。

后续这一批已补齐新版列表范围编译：`Scopes` 保留完整策略，将每条策略的资源范围与环境条件一起转成参数化 SQL，再合并 allow/deny。工作流列表和运行分页使用各自保存的环境 ID，并按所属项目解析环境编码/集群；环境列表也带入集群。SQL 空值和环境编码大小写行为与具体资源判断对齐，过滤先于分页与计数。

工作流详情、编辑、创建和运行详情已使用目标环境上下文；历史运行按运行自己的环境判断，不能借工作流当前绑定绕过历史环境权限。项目关联集群列表也补齐了全局/项目显式拒绝保护。新增隔离 MySQL 验证 SQL 与具体资源判断、分页、真实工作流 handler 的允许/403；这仍不代表监控、日志、AI 等旧模块已经接入。

服务基础定义与独立构建记录的接口目前不带环境上下文，环境条件不会自动变成这些全局资源的读取权；需要对应服务/构建查看授权。不得为了显示列表而去掉环境条件，或把环境权限扩大为整个项目权限。后续模块接入时需逐项提供与详情一致的目标上下文。

继续顺序：新旧模块接口权限适配与组合验收 → 滚动重启与审计闭环 → 版本/缓存/通知/Helm/主机/Agent。审批扩展按用户要求后置。代码完成与正在运行的进程更新分开记录，见 HANDOFF 最新节。

## 管理员如何使用

在「系统管理 → 权限中心」创建资源范围角色，选择所需操作；再在「资源授权」绑定用户/部门、具体项目/服务/环境/集群和有效期。平台角色仅授予平台管理人员。生产管理和集群测试连接可以单独选择，无需使用 `*`。

配置后用普通账号验证本范围列表、跨项目详情拒绝、测试操作允许、未授权生产操作拒绝，并分别验证日志查看/导出。修改角色后刷新权限，切换账号不会继承旧策略。权限中心选项本身不证明尚未适配的旧模块已经生效。

本批验收见 `HANDOFF.md` 最新节与 `local/dev/authorization-foundation-*`。浏览器受控权限数据只验证页面判断，不代表真实受限账号所有后端接口通过。
