# Kubernetes 项目、工作空间与工作负载使用指南

这篇文档只讲一件事：已经添加 Kubernetes 集群以后，怎么一步一步从页面里创建/确认项目、给项目分配集群配额、创建工作空间绑定 namespace，最后看到 Deployment 和 Service。

平台的关系是：

```text
集群
-> 项目
-> 项目资源池/项目集群配额
-> 工作空间/namespace
-> 应用、Deployment、Service、ConfigMap、Secret ...
```

所以只添加集群，看不到 Deployment/Service 是正常的。必须先把集群分配给项目，再在项目集群下面创建工作空间。

## 0. 开始前先确认

1. 已经导入完整初始化 SQL，不只是 `sql/autoops-navicat-core-auth.sql`。
   完整 SQL 里才有 `onec_project`、`onec_project_cluster`、`onec_project_workspace` 这些表。

2. 后端已经启动：

   ```powershell
   cd F:\autoops
   powershell.exe -ExecutionPolicy Bypass -File .\scripts\start-local-backend.ps1 -WithDevops
   ```

3. 前端已经启动并能登录：

   ```powershell
   cd F:\autoops\kube-nova-web
   node .\node_modules\vite\bin\vite.js --host 0.0.0.0 --port 3006
   ```

4. 已经在页面里添加过 Kubernetes 集群，并且测试连接成功。

   页面入口通常是：

   ```text
   左侧菜单 -> 集群管理 -> 集群管理
   ```

## 1. 创建或确认项目

项目有两个相关入口，作用不一样：

```text
系统管理 -> 项目管理
```

这是基础项目维护页。代码里这个页面有“新建项目”按钮。

```text
项目中心 -> 项目管理
```

这是业务侧项目确认页。代码里这个页面主要有“同步全部数据”“成员”“详情”，没有明显的新建项目按钮。

### 1.1 如果已有默认项目

1. 登录前端。
2. 看页面右上角/顶部栏，找到项目下拉框，提示文字是“选择项目支持搜索”。
3. 点开项目下拉框。
4. 选择“默认项目”或你要使用的项目。
5. 页面提示“已切换到「项目名」项目”后，项目选择完成。

如果当前页面出现“请选择项目”或“选择项目”按钮，也可以直接点这个按钮，它会打开顶部项目选择器。

### 1.2 如果没有项目，需要新建

1. 左侧菜单点：

   ```text
   系统管理 -> 项目管理
   ```

2. 点页面左上方的“新建项目”。
3. 在弹窗里填写：

   ```text
   项目名称：例如 demo
   项目描述：例如 本地测试项目
   ```

4. 点“确定”。
5. 新建成功后，在项目列表里找到这个项目。
6. 如果项目选择器切换项目时报“当前项目未授权任何平台”，回到这个项目列表，对该项目做“平台授权”。
7. 在“项目平台”弹窗里，勾选当前要使用的平台。开发环境不确定时，可以先把 Portal、Manager、Workload、Console 这些可选平台都勾上。
8. 点“确定”。
9. 回到页面顶部项目下拉框，选择刚创建的项目。

如果左侧没有“系统管理 -> 项目管理”，说明当前账号/角色菜单没有授权。可以先用完整 SQL 初始化出来的默认管理员账号，或者到“系统管理 -> 菜单管理/角色管理”给当前角色授权 `/system/project` 对应页面。

### 1.3 在项目中心确认项目可见

1. 左侧菜单点：

   ```text
   项目中心 -> 项目管理
   ```

2. 看列表里是否有你的项目。
3. 如果列表为空，点页面上方“同步全部数据”。
4. 弹出确认框后点“确定同步”。
5. 同步完成后确认项目出现在列表中。

成功标志：

```text
项目中心 -> 项目管理
```

能看到项目行，并且行上有“成员”“详情”操作。

## 2. 给项目分配集群配额

这一步会创建项目和集群之间的资源池关系，也就是后端的 `onec_project_cluster`。

### 2.1 进入资源池页面

1. 左侧菜单点：

   ```text
   项目中心 -> 资源池
   ```

2. 页面顶部会有项目选择框，提示文字是“请选择项目”。
3. 在这个项目选择框里选择你的项目。
4. 选择项目后，页面右侧会出现：

   ```text
   卡片视图
   列表视图
   分配资源池
   ```

如果页面提示“请先选择一个项目”，说明还没有在这个页面选择项目，或者顶部全局项目没有正确初始化。

### 2.2 打开分配资源池弹窗

1. 点“分配资源池”。
2. 弹窗标题是“分配资源池”。
3. 第一块是“选择集群”。
4. 在搜索框里输入集群名称或 UUID。
5. 如果不想搜索，点右侧“浏览全部”。
6. 在列表里选择你已经添加并测试通过的集群。

如果某个集群显示“已分配”，说明这个集群已经分配给当前项目，不能重复分配。

### 2.3 选择费用配置

1. 在弹窗里找到“费用配置”。
2. “计费方案”是必选项，必须选择一个费用配置。
3. “计费开始时间”可以不选，不选时默认当前时间。

如果“计费方案”下拉框为空，先去：

```text
系统管理 -> 费用配置
```

创建或确认一条费用配置。

### 2.4 填项目集群配额

继续在“分配资源池”弹窗里填写配额。开发测试可以先填小一点，但必须能覆盖后面工作空间的配额。

建议本地测试值：

```text
CPU 配额：2
内存配额：4Gi
存储配额：20Gi
Pod 数量：20
Deployment：10
Service：10
ConfigMap：10
Secret：10
PVC：5
Ingress：5
```

如果页面有 GPU，但你的集群没有 GPU，可以保持 0。

注意：

```text
CPU、内存、Pod 数量后面创建工作空间时还要继续分配。
项目资源池配额必须大于或等于工作空间配额。
```

### 2.5 提交并同步

1. 点弹窗底部“分配资源”。
2. 成功后页面会出现一个资源池卡片，卡片标题是集群名称。
3. 卡片里能看到 CPU、内存、存储、GPU、Pods 等资源用量。
4. 点卡片右上角三个点。
5. 点“同步状态”。

成功标志：

```text
项目中心 -> 资源池
```

选择项目后能看到集群资源池卡片。

## 3. 创建工作空间并绑定 namespace

这一步会创建项目集群下的工作空间，也就是后端的 `onec_project_workspace`。这里的工作空间基本对应 Kubernetes namespace。

### 3.1 进入工作空间页面

1. 先确认顶部项目下拉框已经选中你的项目。
2. 左侧菜单点：

   ```text
   项目中心 -> 工作空间
   ```

3. 页面顶部只有一个“集群”选择框。
4. 在“集群”下拉框里选择刚才分配给项目的集群。

如果“集群”下拉框为空，回到上一节检查：

```text
项目中心 -> 资源池
```

当前项目是否已经分配过这个集群。

### 3.2 打开创建工作空间弹窗

1. 选择集群后，页面右上角有一个圆形加号按钮。
2. 鼠标放上去，提示是“创建工作空间”。
3. 点这个加号按钮。
4. 弹窗标题是“创建工作空间”。

弹窗分为四步：

```text
基础信息
资源配额
限制策略
确认信息
```

### 3.3 第一步：基础信息

在“基础信息”页填写：

```text
工作空间名称：例如 dev
命名空间：例如 dev
描述信息：例如 开发测试 namespace
```

namespace 规则：

```text
只能小写字母和连字符 -
必须以小写字母开头
必须以小写字母结尾
创建后不可修改
```

示例：

```text
正确：dev
正确：demo-dev
错误：Dev
错误：dev_01
错误：dev-
```

填完点“下一步”。

### 3.4 第二步：资源配额

在“资源配额”页会看到“集群资源概览”，下面是配额表单。

必填项：

```text
CPU 配额
内存配额
Pod 数量
```

建议本地测试值：

```text
CPU 配额：1
内存配额：1Gi
存储配额：5Gi
Pod 数量：10
Deployment：5
Service：5
ConfigMap：5
Secret：5
PVC：2
Ingress：2
```

这里的配额不能超过项目资源池剩余可用量。

如果你后面要看 Deployment，至少给：

```text
Pod 数量 >= 1
Deployment >= 1
```

如果你后面要看 Service，至少给：

```text
Service >= 1
```

填完点“下一步”。

### 3.5 第三步：限制策略

“限制策略”是 LimitRange 配置，是选填项。

页面顶部有快速模板：

```text
小型应用
中型应用
大型应用
自定义
```

开发环境建议直接保留默认“中型应用”，不要先改复杂参数。

如果你要自己改，主要字段包括：

```text
Pod 最大 CPU
Pod 最小 CPU
Pod 最大内存
Pod 最小内存
容器最大 CPU
容器最小 CPU
容器最大内存
容器最小内存
默认 CPU 限制
默认 CPU 请求
默认内存限制
默认内存请求
```

填完点“下一步”。

### 3.6 第四步：确认信息

1. 在“确认信息”页检查：

   ```text
   工作空间名称
   命名空间
   CPU/内存/存储配额
   Pod/Deployment/Service 等对象限制
   限制策略
   ```

2. 点“确认创建”。
3. 二次确认框会提示 namespace 创建后无法修改。
4. 点“确认创建”。

成功标志：

```text
项目中心 -> 工作空间
```

选择集群后能看到刚创建的工作空间卡片或列表行。

## 4. 看 Deployment

推荐从“应用中心”看 Deployment 和应用关系。

### 4.1 进入应用中心

1. 确认顶部项目下拉框已经选中你的项目。
2. 左侧菜单点：

   ```text
   业务中心 -> 应用中心
   ```

3. 页面顶部从左到右选择：

   ```text
   选择集群
   选择工作空间
   选择服务
   全部类型
   ```

4. 先点“选择集群”，选刚才分配的集群。
5. 再点“选择工作空间”，选刚才创建的工作空间。
6. “全部类型”里选择 `Deployment`。

如果这个 namespace 下已经有 Deployment，列表/应用区域会显示出来。

如果你是想在平台里新建一个 Deployment：

1. 仍然在：

   ```text
   业务中心 -> 应用中心
   ```

2. 先选集群和工作空间。
3. 点页面右上方“创建服务”。
4. 弹窗里选择：

   ```text
   表单创建
   ```

   或：

   ```text
   YAML 批量创建
   ```

5. 表单创建适合一步步配置工作负载、版本、容器。
6. YAML 批量创建适合直接粘贴 Kubernetes YAML。

如果点击“创建服务”时提示资源配额不足，回到：

```text
项目中心 -> 工作空间
```

编辑工作空间，把 CPU、内存、Pod、Deployment 或 Service 配额调大。

### 4.2 如果有单独的工作负载菜单

有些菜单配置会开放这些入口：

```text
业务中心 -> 工作负载 -> Deployment 管理
业务中心 -> 工作负载 -> Pod 管理
业务中心 -> 工作负载 -> StatefulSet 管理
业务中心 -> 工作负载 -> Job 管理
业务中心 -> 工作负载 -> CronJob 管理
```

如果你的左侧菜单能看到“工作负载”，也可以直接进入“Deployment 管理”。进入后同样先选择项目、集群、工作空间。

如果菜单里看不到“工作负载”，优先使用：

```text
业务中心 -> 应用中心
```

## 5. 看 Service

Service 有两个容易混淆的位置。

### 5.1 看 namespace 里的 Kubernetes Service 列表

用这个入口：

```text
业务中心 -> 配置管理
```

步骤：

1. 左侧菜单点“业务中心”。
2. 点“配置管理”。
3. 页面顶部先选“选择集群”。
4. 再选“选择工作空间”。
5. 下面有多个 Tab：

   ```text
   ConfigMap
   Secret
   Service
   Ingress
   PVC
   ServiceAccount
   Role
   RoleBinding
   ```

6. 点 `Service` Tab。

这里看到的是当前 workspace/namespace 下的 Kubernetes Service。

### 5.2 看某个应用自己的服务管理

用这个入口：

```text
业务中心 -> 应用中心
```

步骤：

1. 选择集群。
2. 选择工作空间。
3. 在应用/服务列表里点一个应用。
4. 右侧详情区域有这些 Tab：

   ```text
   基础信息
   版本管理
   服务管理
   Ingress管理
   Flagger 发布
   日志查询
   操作审计
   ```

5. 点“服务管理”。

这里看到的是某个应用关联的 Service，不是 namespace 下所有 Service 的总列表。

## 6. 最短点击路径

如果你只想最快走通一次，按这个顺序点：

```text
1. 集群管理 -> 集群管理
   添加集群/测试连接

2. 系统管理 -> 项目管理
   如没有项目，点“新建项目”
   如项目未授权平台，给项目做“平台授权”

3. 顶部项目下拉框
   选择项目

4. 项目中心 -> 资源池
   选择项目
   点“分配资源池”
   选择集群
   选择计费方案
   填 CPU/内存/Pod/Deployment/Service 配额
   点“分配资源”
   回到资源池卡片，点三个点 -> 同步状态

5. 项目中心 -> 工作空间
   选择集群
   点右上角加号“创建工作空间”
   基础信息：填工作空间名称和 namespace
   资源配额：填 CPU/内存/Pod/Deployment/Service
   限制策略：默认中型应用
   确认信息：点“确认创建”

6. 业务中心 -> 应用中心
   选择集群
   选择工作空间
   全部类型选择 Deployment

7. 业务中心 -> 配置管理
   选择集群
   选择工作空间
   点 Service Tab
```

## 7. 常见问题

### 7.1 顶部项目下拉框没有项目

可能原因：

```text
完整 SQL 没有导入
项目没有创建
当前账号没有项目权限
项目没有授权当前平台
```

处理：

```text
1. 确认完整导入 sql/autoops-navicat-init.sql 或 sql/db-init.sql
2. 系统管理 -> 项目管理，新建或确认项目
3. 给项目做平台授权
4. 重新登录或刷新页面
```

### 7.2 工作空间页面没有集群可选

原因通常是项目还没有资源池。

处理：

```text
项目中心 -> 资源池
选择项目
分配资源池
选择集群
提交
```

### 7.3 创建工作空间时报资源不足

原因是工作空间配额超过了项目资源池剩余量。

处理：

```text
项目中心 -> 资源池
找到集群资源池卡片
三个点 -> 编辑配额
调大 CPU/内存/Pod/Deployment/Service
```

或者在创建工作空间时把工作空间配额填小一点。

### 7.4 应用中心选不到工作空间

检查顺序：

```text
顶部项目下拉框是否选对项目
应用中心里“选择集群”是否选对集群
项目中心 -> 工作空间 是否能看到该 workspace
workspace 是否属于当前项目和当前集群
```

### 7.5 Service Tab 是空的

可能原因：

```text
namespace 里确实没有 Service
选错了项目/集群/工作空间
Service 配额为 0，平台无法创建新的 Service
Kubernetes 连接异常
```

处理：

```text
1. 先确认业务中心 -> 配置管理 -> Service Tab 选的是正确 workspace
2. 如果只是想看已有 K8s Service，确认集群里该 namespace 真的有 Service
3. 如果想通过平台创建 Service，确认工作空间 Service 配额 >= 1
```

### 7.6 Deployment 看不到

可能原因：

```text
namespace 里没有 Deployment
应用中心筛选类型不是 Deployment
选错了项目/集群/工作空间
工作空间 Deployment 或 Pod 配额为 0
```

处理：

```text
1. 业务中心 -> 应用中心
2. 选择正确集群
3. 选择正确工作空间
4. 全部类型选择 Deployment
5. 如果要新建，点“创建服务”
```

### 7.7 Prometheus 报错和 Deployment/Service 无关

如果日志里出现类似：

```text
Get "http://http//prom.sinozo.com:80/-/healthy"
```

这是 Prometheus 地址格式问题，主要影响监控图表，不是 Deployment/Service 看不到的主因。

正确格式通常是：

```text
http://prom.sinozo.com:80
```
