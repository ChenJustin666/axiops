# 模板库与服务配置

## 本次结论

模板创建从数据库模板库取已保存内容；Kubernetes YAML 服务在创建时选择环境并填写模板参数，保存该环境的独立副本。手动创建从空白 YAML 开始，不自动套模板。

用户示例中的 Deployment 与 Service 如果写在同一个文件中，必须用 `---` 分隔；分成两个模板文件时，平台生成服务快照会加入分隔符。

## 使用方式

- 入口：**CI/CD → 模板库**，地址 `/cicd/templates`。顶部为 K8s YAML、Helm Chart、Dockerfile、构建四类；左侧列表、中间文件编辑、右侧变量或说明。
- 支持创建、修改、校验、另存为、下载当前文件和归档。离开未保存内容会提醒；版本冲突保留本地修改，不覆盖别人已保存的版本。
- 服务配置左侧“模板”打开加宽、加高的对话框，按项目类型显示 K8s YAML 或 Helm Chart 已保存模板。K8s YAML 选择环境、模板后点击“下一步”，填写服务名称和模板参数；Env/JVM、模板健康检查、其他参数分别折叠，有监控参数时健康检查分组才包含“监控”。模板已有健康检查参数或原生探针时，隐藏重复的可选探针入口。可选资源点击“+”逐项填写并“完成添加”，支持多个完成项共存、编辑和删除；完成或删除后自动生成后端渲染的“最终 YAML 预览”，包含资源及挂载引用。“预览完整配置”也可手动刷新，修改参数后需重新预览。预览不保存、不部署；Image 是校验占位值，已有 Secret 只展示引用。“高级：编辑模板 YAML”单独提供模板源文编辑，隐藏内部变量元数据注释。禁止点击遮罩意外关闭。
- 手动 Kubernetes YAML 目录从空白开始，粘贴原生配置即可；也支持系统变量 `{{.Service}}`、`{{.Image}}`、`{{.Namespace}}`。只有模板模式提供模板创建参数和可选能力表单；手动引用自定义占位符时仍可填写变量值。Helm/主机沿用各自交付流程。
- 选用后文件和变量可继续编辑，保存前先校验。切换模板须确认替换内容，取消后下拉恢复已应用项。旧服务异步读取不会覆盖新选中的服务，读取失败阻止保存。
- 修改或归档模板不会更新已有服务、环境或者触发部署；需要在服务配置中明确选择目标环境、更换模板并保存。模板参数支持可选显示名称和分组，不需要改前端才能增加普通参数。

## 四种类型的实际范围

### Kubernetes 可选资源的管理范围

| 配置 | 创建与修改方式 | 数量与边界 |
| --- | --- | --- |
| Ingress | 域名、路径、Ingress Class、已有 TLS Secret | 可添加多个；重复域名与路径会阻止保存。DNS 和 Ingress Controller 由集群提供。 |
| PVC | 新建容量/StorageClass 或引用已有 PVC，填写挂载目录 | 可添加多个；解除引用不删除数据，既有 PVC 的扩容不在此表单中执行。 |
| ConfigMap | 新建文本文件或引用已有 ConfigMap 的键，填写完整挂载路径 | 可添加多个文件；重复或相互覆盖的挂载路径会拒绝。复杂原生 ConfigMap 可编辑 YAML。 |
| Secret | 模板表单引用已有 Secret 的键，注入 Env 或挂载文件 | 可添加多个引用。创建后在“配套配置”新建多键加密凭据；模板库不存密码正文。生成的应用 Secret 为 Opaque；Ingress TLS 使用已存在的 TLS 类型 Secret。 |
| HPA | 最小/最大副本、CPU 目标利用率 | 每个工作负载一份；需要 CPU request 和集群指标服务。高级指标使用原生 YAML。 |
| 探针 | HTTP/TCP、端口与路径 | 每个工作负载一组；模板已有探针时不重复添加，TCP 不需要 HTTP 路径。 |
| 监控注解 | 指标端口、路径 | 每个工作负载一组；集群需配置对应采集方式。 |

Ingress、PVC、ConfigMap 文件和 Secret 引用可重复点击“+”添加，完成项独立编辑、移除；编辑一项时先完成或取消，再编辑下一项。删除其中一项不会重命名其他资源。HPA、探针与监控配置不重复添加。可选表单面向单 Deployment、单 Service、单容器模板；多工作负载、复杂调度和其他已支持的资源使用原生 YAML，不能把此表单理解成覆盖全部 Kubernetes 控制器。

完成项参与同一次后端渲染和校验。最终预览显示已替换变量的 YAML；引用已有资源时显示引用，Secret 正文不显示。保存只写当前服务、当前环境；发布通过工作流执行。

| 类型 | 内容与使用范围 |
| --- | --- |
| K8s YAML | 多文件 YAML + 自定义变量默认值；系统身份/镜像变量由部署注入，环境变量可覆盖默认值。 |
| Helm Chart | 完整 v2 application Chart，按现有 Helm 导入的不可变 JSON/文件摘要格式保存。参数维护在 values.yaml；声明的依赖必须包含在 charts/。 |
| Dockerfile | 可维护、下载，提交到代码仓库后在构建配置选择路径。本次不自动提交或改写远端仓库。 |
| 构建 | 单个 build.yaml，支持 build_image、build_command、可选 cache_dir；在 JAR 镜像/产物构建配置中选择应用。不携带凭据或目标环境。 |

内置 Kubernetes 模板为 Deployment + ClusterIP Service，默认 1 副本、8080 端口；必须按应用实际端口修改。不覆盖镜像 ENTRYPOINT，不设置不合理的固定资源限制。探针、Spring/Nacos 等应用环境配置仍需按服务补齐，模板可保存这些普通配置。Helm 基础 Chart 的示例镜像也需配置，不能直接当作可部署业务应用。

模板变量默认值需要完整，以便新建服务可校验；这不是跨环境自动同步功能。已有服务的环境专属配置、业务数据和生产资源没有被本次代码改写。旧的构建快捷预设仍保留，构建模板库是新增的可维护入口。

## 存储和权限

- 迁移 `039_delivery_templates.sql` 新增 `delivery_template`，保存分类、文件、变量、revision、内置键与归档状态。
- API 启动幂等初始化四个内置模板，不覆盖管理员修改或恢复已归档模板。
- API：`GET/POST /api/v1/delivery-templates`、`PUT/DELETE /api/v1/delivery-templates/:id`、`POST /api/v1/delivery-templates/preview`。前端经 `/api/cicd/v1` 代理访问。
- 沿用 `build_template` 权限：获授权用户可读取；跨项目共享模板的新增、修改和归档需要平台范围权限。服务保存仍检查原服务权限。
- 请求限制 1 MiB、文件内容合计 512 KiB、最多 64 文件/变量；拒绝路径穿越、重复文件、系统变量覆盖、非法请求字段。YAML 校验会发现缺值、重复键（常见于漏 `---`）及现有执行器不支持的资源；Helm 会进行本地默认 values 渲染，不访问集群。
- 校验并非 Kubernetes server-side dry-run，也不证明镜像可拉取或应用健康。
