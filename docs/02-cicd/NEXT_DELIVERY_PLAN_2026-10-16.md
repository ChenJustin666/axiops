## 第 1 批：权限与重启

### 使用方式与权限模型

默认使用角色模板加资源范围，不要求用户逐条编写策略。入口优先放在“项目设置 → 成员与权限”；平台层管理共享角色模板和授权审计。角色模板是建议目标，需要与现有权限中心整合，不能再造平行账号体系。

| 角色模板 | 建议默认能力 |
| --- | --- |
| 项目管理员 | 管理项目配置、成员及项目资源；平台共享凭据与节点管理另外授权 |
| 开发者 | 查看、编辑获授权服务和非生产配置、运行获授权构建/测试；不自动取得生产发布和重启权 |
| 发布操作员 | 对指定环境执行发布、回滚、重启；配置编辑与成员管理单独授权 |
| 只读成员 | 查看获授权项目、服务、环境状态和允许的日志；不能保存、构建、发布、回滚、重启或读取凭据正文 |

支持“仅项目 A”“仅服务 A/B”“仅测试环境”等限制。服务范围与环境范围必须同时生效；不能因为能看环境就绕过服务限制。未明确授权拒绝访问，显式 deny 优先。列表、搜索、计数、详情、日志、Commit/制品链接和通知深链接都遵守同一可见范围。日志也可能含敏感信息，需要脱敏和明确权限。Secret 正文默认不展示，引用/使用/修改与查看元数据区分。

不能仅隐藏按钮：直接调用 API、改 URL/ID、使用已打开页面或权限变更后的旧会话同样应被阻止。生产操作独立授权，不因项目普通编辑权自动开放。跨项目管理员不能授予自己未拥有的权限。保留删除项目的现有保护。

### 重启语义

- 环境资源列表中的 Deployment、StatefulSet、DaemonSet 提供“重启”；确认框明确环境、集群、Namespace、资源名以及可能的服务影响。界面紧凑，结果与事件就地可看。
- 默认触发控制器滚动重启，复用当前运行镜像与配置；不重新构建，不从编辑器草稿部署，不修改副本或运行参数。
- Kubernetes 没有通用的“重启单个容器”接口。此版本定义为工作负载重启；不把直接删除 Pod 偷换成无影响的容器操作。
- OnDelete 更新策略不能仅打注解就报告重启成功；第一版明确阻止并说明策略不支持自动滚动重启。零副本不自动扩容、暂停的 Deployment 不悄悄恢复。独立 Pod/Job/CronJob 不显示通用重启入口。
- 后端从环境解析真实目标并校验服务/工作负载归属、UID、权限及目标未变化，不接受客户端随意指定集群/Namespace；避免旧页面操作到重建后的同名资源。
- 与发布/回滚使用兼容的资源互斥规则和重复提交保护；网络返回不明时核对原操作，不无限重复修改模板注解。
- 接口收到请求、Kubernetes 接受修改、工作负载就绪是不同阶段。保存操作人/目标/起止时间/操作 ID/失败原因与事件；提交成功不能直接显示“重启完成”。
- 保留生产确认和现有安全策略；单副本或受资源/探针限制的服务不能承诺零中断。

### 首批验收

1. 管理员、只读、仅服务、仅环境、生产无操作权、显式拒绝、其他项目账号逐项验证列表和接口。
2. 通过受控 Kubernetes API 或 fake client 验证修改仅限正确资源的 Pod 模板注解；目标/UID/版本变化、403、404、集群不可达、重复点击均有确定结果。
3. 验证发布中重启、重启中发布、服务删除/环境改绑、OnDelete、暂停、零副本、超时和平台重启恢复。
4. 浏览器验证按钮权限、确认目标、执行状态、失败信息、刷新恢复和窄屏；真实集群动作仅在明确的测试资源完成，不用用户生产服务做验收。

## 第 2–3 批：版本与缓存

版本管理按“服务 → 制品版本 → 各环境部署记录”展示。版本详情同时显示 Commit/分支、构建号、镜像 tag 与 digest 或包 checksum、构建时间、配置版本、目标环境、执行人、发布与回滚状态。允许可读版本名，但不可代替 digest/checksum 身份。当前部署版本、历史成功版本、推荐发布版本区分；优先复用已有镜像，生产不因 tag 含 test 重新构建。

环境回滚按服务选择历史成功部署快照；多服务只回滚明确选择的服务，说明恢复的是哪份制品与配置。版本保留策略必须保护正在运行和可回滚引用的制品，平台删除记录与远端仓库清理分开。不能假设私有仓库镜像永远存在。

缓存首先按 CI 构建缓存处理。默认无需业务用户填写路径，系统管理配置缓存后端，服务构建设置提供“继承/关闭/专用策略”，并展示实际生效策略。Maven/Gradle/npm/Go 等依赖缓存与 BuildKit 层缓存分开说明；Dockerfile 必须显式使用支持的机制才能承诺命中。

缓存按项目/服务/工具链/必要锁文件等设计 key 和回退规则；区分可信构建与不可信分支，防止凭据泄漏和缓存污染。缓存只加速，源码与最终制品不放进缓存生命周期。RWO/RWX、多节点与同服务并发需明确可用性和一致性策略，不因共享 PVC 就宣称可并发写；显示命中信息、容量、最近使用和单独清理。失效缓存可受控回退并清楚记录，不能无限重试或隐藏磁盘错误。验证冷构建、热构建、依赖更新、损坏、后端不可用、并发、清理和磁盘满。

## 第 4 批：个人与群通知

- “根据登录账号通知”定义为根据运行保存的实际执行人/触发归属通知，不取 Worker 执行时某个浏览器的登录用户。个人设置绑定飞书/钉钉/企业微信账号身份；用户名不能直接当手机号或渠道 open_id。
- 项目设置管理群接收；个人订阅只影响自己，群订阅需要项目管理权限。支持成功/失败/取消事件、关注环境与服务；凭据加密，URL/token/签名密钥不出现在日志。
- 第一阶段企业微信机器人/应用用于企业接收场景；个人微信不等同企业微信，也不存在可通用依赖的个人微信群机器人。若需个人微信，另选官方可用的公众号/服务通知接入方案。
- 飞书/钉钉签名、企业微信响应等分别适配，判断 HTTP 与平台业务结果，支持有限重试、去重、投递记录、停用与重发。异步投递失败不改变已经完成的部署结果。
- 通知只含允许公开的结果摘要与受鉴权的深链接，不带 Secret、全部配置或完整日志。Webhook/定时任务没有人工执行人时使用明确的触发归属和项目订阅，不随机选择在线账号。
- 以本地受控接收端验证载荷、签名、HTTP 200 业务失败、超时重试与队列恢复；真实飞书/钉钉/企业微信需测试群凭据，并只向用户明确指定的测试接收方发送。

## 第 5–7 批：三类执行方式

Helm 继续使用官方 SDK，固定 Chart 版本与内容摘要、依赖及环境 values；普通环境参数清楚，复杂 values 原生可编辑。预览、安装、升级、就绪、失败、历史与回滚身份一致，保护既有 release；Chart Secret 脱敏，目标 Namespace 不漂移。首次安装失败与升级失败分别验收。

主机应用围绕下载校验制品 → 准备 → 切换版本 → 健康检查 → 保留恢复点设计，前端展示主机清单、批次与每台执行状态。凭据、环境配置和工作目录不混用；长任务/掉线/平台重启不重复执行部署脚本。脚本无法完全自动保证幂等，要通过持久化步骤记录与显式恢复策略实现。部署与构建节点概念分开。

Agent 构建节点在构建资源下单独管理：注册一次性令牌、标签/架构、能力、在线状态、并发、CPU/内存、工作目录、缓存与保留、暂停接单/排空/撤销。任务按项目授权和能力调度，队列与租约可恢复；每任务隔离工作区、短时凭据、按次日志和制品校验。第一版明确 Linux 版本/架构与构建工具支持矩阵，不笼统承诺 Windows/macOS 构建。主机上直接执行脚本的信任边界必须清楚，不默认向不可信代码提供生产节点或高权限 Docker socket。

## 第 8 批：自动化测试与 DevSecOps

先做单元/接口测试和 JUnit 等结构化报告、超时/取消与结果保存，再按需加代码静态检查、依赖漏洞、镜像扫描和 SBOM。扫描工具和执行镜像版本固定；镜像扫描对准确 digest，报告绑定服务、Commit、制品和运行，不能扫描 A 制品却放行 B。

默认提供可选流水线模板，沿用现有独立 Job，避免把任意脚本放到 API/Worker 本机执行。策略区分提示、阻断、可追踪的例外与有效期；工具失败/报告缺失不能冒充扫描通过。生产环境按团队选定策略验证制品已有的测试与扫描证据，镜像复用时不需要重复编译。漏洞数据库更新、误报、报告保留和跨项目可见性均需有规则。质量门禁与审批是不同能力，本阶段不顺带扩建审批。

## 每批交付规则

每批完成前后端接口、必要迁移与兼容、故障路径、权限与并发回归、浏览器桌面/窄屏、操作教程和 HANDOFF；有外部条件未验证时明确列出。使用隔离数据库/测试资源，不把模拟接口测试当真实部署通过，也不把已有文件或测试名称当功能完成证明。下一批从本文件记录的结果继续，无需用户反复确认同一方案；真实外部消息、真实生产变更等仍按用户具体授权执行。
