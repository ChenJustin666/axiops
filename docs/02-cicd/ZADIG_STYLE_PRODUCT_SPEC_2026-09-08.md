# AxiOps CI/CD Zadig 风格产品规格（冻结版）

## 1. 设计决策

AxiOps 不直接复用 `reference/zadig-portal` 的代码。该仓库是 Vue 2 + Vuex + Element UI + Webpack，AxiOps 是 Vue 3 + Pinia + Element Plus + Vite，直接混用会带来路由、状态、权限和接口模型冲突。

采用“源码研究 + 交互重写”：页面结构、向导步骤、服务树、编辑器/变量侧栏、环境配置和工作流展示按 Zadig 对齐；数据模型、API、权限、Revision、构建和发布执行继续使用 AxiOps 的实现。

## 2. 页面主线

```text
项目列表
  -> 创建项目（只配置项目元数据和项目类型）
  -> 项目初始化向导
       1. 项目配置
       2. 新建服务
       3. 创建环境
       4. 执行工作流
```

项目创建页不导入 YAML、不选择 Git 文件、不配置服务变量。服务定义必须在“新建服务”步骤完成，这一点是当前实现需要纠正的核心。

## 3. 图 1：项目列表

- 左侧为 AxiOps 全局导航，当前模块高亮“CI/CD -> 项目”。
- 顶部提供项目搜索、卡片/列表切换和“新建项目”。
- 项目卡片显示：项目名称、项目类型图标、描述、创建人、更新时间、服务数、环境数、最近运行状态。
- 支持项目分类或标签，但不把分类和交付类型混为一项。
- 卡片点击进入项目初始化向导或项目工作区；权限不足的项目不出现在列表中。

## 4. 图 2：创建项目

创建项目只填写：

| 字段 | 规则 |
| --- | --- |
| 项目名称 | 必填，项目内唯一 |
| 项目标识 | 自动生成，可授权用户修改；创建后默认不可随意改变 |
| 描述 | 可选 |
| 项目类型 | K8s YAML、K8s Helm Chart、主机应用 |
| 高级配置 | 后续扩展，不阻塞首次创建 |

创建后进入项目初始化向导的第一步。项目类型决定后续服务解析器、环境目标和部署执行器，但不改变统一的项目/服务/环境/工作流抽象。

## 5. 图 3：新建服务

第二步左侧是服务树，支持一次导入多个服务；中间是定义编辑器；右侧是变量、组件和构建配置。

服务创建入口只有三个：

1. **手工输入**：填写服务名称，在 YAML 编辑器中直接输入一个或多个 Kubernetes 资源。
2. **从代码库同步**：选择平台已授权的 Gitea/GitLab/GitHub/Gitee 代码源、仓库、分支和目录；目录下每个服务目录可生成一个服务。
3. **使用模板新建**：选择模板后预览模板定义，再填写服务变量并生成服务。

服务元数据包括服务名称、服务编码、代码源/仓库/分支（手工输入可为空）、定义目录、镜像仓库和构建配置。服务保存后创建不可变 Revision；继续编辑必须生成新 Revision。

服务树要求：

- 左侧显示服务列表、资源类型和定义状态；支持新增、复制、删除/停用、搜索和批量同步。
- 选中服务后，中间显示 YAML/Helm/主机定义；右侧显示组件、镜像、系统变量、自定义变量和构建入口。
- 多服务导入后，每个服务独立拥有 Revision、构建配置和环境覆盖。
- 删除采用停用，不破坏历史 Revision、运行记录和环境引用。

## 6. 图 4/5：模板新建与预览

模板新建弹窗字段：服务名称、模板选择、变量表格、自动同步开关、预览折叠区。

模板选择后必须显示：

- 模板名称、版本、来源和更新时间。
- 模板定义的只读预览。
- 变量 Key、说明、默认值、输入值和必填标识。
- 预览结果中的资源列表、容器名称、镜像地址、端口、副本和资源限制。

模板渲染使用明确的模板语法。K8s YAML 模板沿用当前 Zadig 兼容格式，例如 `{{.replicas}}`；Helm Chart 使用 Helm v3 values 语义，不把两种语法混在同一个解析器中。

## 7. 图 6：创建环境

第三步顶部是环境标签页。项目不强制拥有 dev/test/stage/prod 全部环境，用户可保留 `dev`、`qa` 两个环境，也可删除或继续添加环境。

每个环境配置：

| 字段 | K8s YAML/Helm | 主机应用 |
| --- | --- | --- |
| 环境名称/编码 | 必填 | 必填 |
| 资源目标 | 集群 + Namespace | 主机组 |
| 镜像仓库 | 可从平台默认值继承 | 制品仓库 |
| 是否生产 | 用于审批和门禁 | 用于审批和门禁 |
| 环境变量 | 环境级覆盖 | 环境级覆盖 |
| 服务选择 | 从项目服务中选择，可批量加入 | 从项目服务中选择 |

集群必须来自当前用户有权限且状态为 connected 的集群。环境可以删除，但已经被运行记录或发布引用时只能停用。环境创建完成后，系统生成服务×环境绑定；未加入环境的服务不出现在该环境的发布列表。

## 8. 变量模型

变量分三层，优先级从高到低为“服务/环境覆盖 -> 项目变量 -> 系统内置变量”：

### 系统内置变量

```text
$Product$       项目名称
$Service$       服务名称
$Namespace$     当前环境 Namespace
$EnvName$       当前环境名称
$ClusterName$   当前集群名称
$Image$         当前服务构建产物镜像或 digest
```

### 模板服务变量

模板可声明 `cmd`、`cpuLimit`、`memoryLimit`、`port`、`replicas` 等变量。例如：

```yaml
replicas: {{.replicas}}
command:
  - /workspace/{{.cmd}}
containerPort: {{.port}}
resources:
  limits:
    cpu: {{.cpuLimit}}
    memory: {{.memoryLimit}}
```

### 项目/环境变量

- 项目变量用于多个服务共享的非敏感配置。
- 环境变量用于 dev/qa/prod 差异化配置。
- Secret 只能引用凭据 ID，不在列表、日志、预览或 Diff 中返回明文。
- 页面支持“使用全局变量”勾选、变量来源标识和最终渲染值预览。

## 9. 下一步与工作流

完成环境配置后进入第四步“执行工作流”：

- 默认生成项目级工作流模板，不为每个环境复制一套定义。
- 运行时按“服务 × 环境”生成独立 Job，Job 显示环境、服务、集群、Namespace、镜像 digest 和状态。
- 一个项目可以只有测试和生产；生产发布前必须经过测试验证和审批。
- 工作流节点至少包含源码、构建、测试、部署、审批、通知；YAML、Helm、主机部署节点允许不同参数，但统一展示阶段状态。
- 同一个构建产物在 dev/qa/stage/prod 之间晋级，不在每个环境重复构建。

## 10. 项目工作区布局

初始化完成后的工作区不再使用当前“服务目录 + 服务矩阵 + 详情面板”混合首屏，改为：

1. 项目顶部：名称、类型、状态、服务数、环境数、运行中任务。
2. 项目级页签：概览、服务、环境、工作流、运行记录、制品、变量与模板、通知、设置。
3. 服务页：左服务树、中定义编辑器、右变量/构建/环境引用；环境发布在独立环境页签和发布抽屉完成。
4. 环境页：环境标签页 + 集群/Namespace 信息 + 服务列表 + 环境变量 + 渲染预览 + 发布按钮。
5. 工作流页：工作流模板列表、节点图、运行入口和运行历史。

## 11. P0 重构顺序

1. 重做项目列表和创建项目页，严格区分项目配置与服务配置。
2. 重做初始化向导壳和服务三栏页，接入手工/YAML、代码库、模板三种入口。
3. 重做模板预览和变量表格，支持多个服务连续创建。
4. 重做环境标签页、服务绑定和变量继承。
5. 重做工作流模板/环境 Job 展示和运行详情。
6. 最后接入 Helm Chart 文件树、主机应用向导和高级发布策略。

## 12. 验收门槛

- 项目创建页不出现 YAML、仓库文件或服务变量字段。
- 服务页能连续创建多个服务，左树切换不会丢失编辑状态。
- 手工、代码库、模板三种服务入口均能创建 Revision；模板能预览渲染结果和变量说明。
- 环境可以只保留 dev/qa，也可以添加或删除环境；服务只有加入环境后才显示为该环境发布目标。
- 变量来源、最终值、Secret 脱敏和环境覆盖 Diff 可解释。
- 1440/1280/1024 宽度不裁切核心操作区；小屏自动转为上下结构。
- 加载、空数据、无权限、失败和停用状态均有明确中文反馈，不显示空白或无意义的“系统内部错误”。
