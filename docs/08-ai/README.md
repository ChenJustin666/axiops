# AI 运维模块

## 产品设计

AI 首期作为只读运维助手，完成告警解释、日志归纳、证据关联、巡检建议和 SOP 推荐，不直接获得平台管理员权限。

## 需求

- 查询范围不得超过当前用户权限。
- 回答必须附指标、日志、事件或变更证据。
- 写操作生成 pending action，经 API 权限、审批和确认执行。
- 支持私有模型或外部模型 provider，敏感数据可脱敏。

## 技术设计

AI 通过 Tool Registry 调用受控平台 API，不直连业务数据库或 Kubernetes。详细产品设计见[DESIGN.md](DESIGN.md)，风险边界见[SECURITY.md](SECURITY.md)。

## 实施计划

1. 实现只读证据查询工具。
2. 实现告警解释、日志归纳和变更关联。
3. 实现会话审计、引用和反馈。
4. 实现 pending action，但默认不开放自动执行。
5. 权限与评测成熟后再增加受控自动化。

## 完成进度

- 已完成：产品定位、安全边界、Tool/SOP/Pending Action 设计。
- 未开始：目标 observability/ai API 和前端。

## 验收标准

- 越权问题返回无权限，AI 不得换工具绕过。
- 每项结论可追溯证据和查询时间。
- 高风险动作未经确认不能执行。
