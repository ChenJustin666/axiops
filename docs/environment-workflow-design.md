# 环境、服务配置与工作流使用说明

本轮范围：环境按需创建、环境配置隔离与对比、工作流模板创建、部署目标校验。审批按用户要求后续完善，不新增审批模板或自动插入审批节点。已有生产环境保护规则继续生效。

## 各入口负责什么

| 入口 | 内容 | 保存后的效果 |
| --- | --- | --- |
| 模板库 | K8s YAML、Helm Chart、Dockerfile、构建、工作流模板 | 保存可复用模板，不更新已有服务或流程 |
| 服务配置 | 共享 YAML/Chart、手动新建 YAML、默认变量、各环境覆盖 | 保存配置版本，不自动部署 |
| 环境 | 运行目标：集群和命名空间，或主机组 | 按所选环境展示实际资源、状态、事件和日志 |
| 工作流 | 按模板创建的独立流水线，可以继续编排 | 保存定义；点击执行后才创建运行记录 |
| 运行记录 | 本次节点快照、目标环境、进度、日志和失败原因 | 保留本次执行证据 |

## 创建环境

1. 初始化默认填写一个测试环境 `qa`，选择集群并检查命名空间。
2. 可添加开发 `dev`、预发布 `staging`、生产 `prod` 预设，也可自定义名称和编码；不要求一次创建全部环境。
3. 项目创建后，随时到项目的环境页面点击“新建环境”。例如一个月后新增生产环境，仍在同一项目下创建。
4. 新环境独立选择集群、命名空间或主机组。生产预设使用 `项目编码-prod`，不推断或沿用测试目标。
5. 到服务配置中将需要的服务加入新环境，再核对该环境的配置。新增环境不自动部署，不自动复制其他环境的账号密码、域名或存储。

## 管理环境差异

优先使用标准 YAML/Chart 模板。需要 ConfigMap、Ingress、PVC 等资源时，在服务配置中选择模板或新建 YAML 文件。端口、副本、域名和中间件地址通过模板变量及环境覆盖维护。

账号密码使用加密凭据引用，普通 YAML 编辑器不保存明文 Secret。已有 Secret 可以引用，但必须存在于目标命名空间。

在服务配置中切换环境后修改该环境覆盖；通过“对比其他环境的配置”查看已保存的变量、版本、文件、域名、存储和凭据引用差异。凭据只比较引用，不显示正文。

同步时显式选择目标环境和字段，先预览差异再保存。同步不自动部署，不默认勾选全部环境，不隐式复制敏感配置。修改共享模板也不会自动改变已绑定的环境版本。

## 从模板创建工作流

1. 在“模板库 → 工作流”创建或维护 `workflow.json`。可从内置“仅构建”或对应交付类型的“构建与部署”模板开始。
2. 模板使用当前支持的节点类型和 DAG 依赖；模板中的 `service_id`、`service_revision_id` 为 `0`。具体服务和环境在创建工作流时选择。
3. 在“项目 → 工作流 → 新建工作流”选择模板、服务、名称；编码自动生成，也可修改。
4. 有部署节点时必须明确选择环境。仅构建流程无需部署环境。
5. 创建后可以打开编排，调整节点、分支和命令。保存不执行；点击执行后查看确认页面和运行记录。
6. 模板被修改后，不会自动改写已有工作流。另一环境应新建一个独立部署工作流，复用相同模板。

工作流模板与服务构建模板不同：前者定义步骤与依赖，后者定义编译镜像、编译命令、缓存目录。

## 防止环境混用

- 部署流程的目标环境一旦绑定，不可在运行弹窗临时改成其他环境。
- 老的未绑定部署流程需要在编排中明确选择一次目标环境；系统不会通过名称猜测环境。
- 后端检查项目归属、环境状态、绑定状态、权限及部署类型；创建运行时再次检查工作流版本与目标快照。
- Worker 在提交 YAML、Helm、主机部署前校验目标快照；环境集群、命名空间或主机组发生变化时阻止该次部署。
- 主机组成员清单仍由现有主机解析器解析，本轮不承诺完整冻结主机配置和成员。

## 能力边界

本轮内置流程仅覆盖已有构建和部署执行器。金丝雀、蓝绿、数据库执行、Android 专用打包不作为已支持功能展示；它们需要配套执行器、产物处理、失败恢复和验证，不能只增加模板名称。

审批后续单独设计。现有生产环境或显式要求审批的环境仍沿用原有保护规则；本轮模板不会自动添加审批步骤。
