# AxiOps CI/CD 与 Zadig 交互对齐设计

更新时间：2026-09-06

## 1. 对齐目标

本文件定义 AxiOps CI/CD 按 Zadig 产品方式重构的范围。目标是复刻约 80% 的用户流程和页面信息架构，保留 AxiOps 已有的企业权限、加密凭据、多云集群和微服务边界，不直接复制 Zadig 的实现代码。

本地参考来源：

- `reference/zadig/System-Architecture-Overview-zh-CN.md`：Zadig 入口、Aslan 核心业务、Workflow Runner、Job Executor、Job Agent、MongoDB/MySQL 和 Kubernetes 数据平面。
- `reference/zadig/pkg/types/repo.go`：代码库模型支持 source、owner、namespace、branch、tag、commit、PR、checkout path、子模块和主仓库标识。
- `reference/zadig/pkg/types/workflow.go`：参数类型包括 string、choice、multi-select、image、script、file，工作流构建支持代码库或模板库 Dockerfile。
- `reference/zadig/pkg/util/yaml.go`、`pkg/util/yaml/merge.go`：多 YAML 合并、拆分、确定性顺序和覆盖合并。
- `reference/zadig/examples/multi-service-demo`、`examples/voting-app/freestyle-k8s-specifications`：一个目录一个服务、同级目录多个服务和 Helm Chart 文件组织方式。

## 2. Zadig 的真实产品主线

Zadig 的核心不是单个发布按钮，而是下面的闭环：

```text
项目类型
  -> 服务目录/服务组件
  -> 代码库与构建配置
  -> 环境服务矩阵与变量组
  -> 工作流 DAG
  -> 运行详情、日志、测试、发布、回滚
```

页面上下文始终保留当前项目、服务、环境和版本；开发人员从项目进入服务配置，运维人员从环境或工作流进入发布，而不是把所有配置堆在一个长弹窗里。

## 3. 三类项目流程

### 3.1 K8s YAML 项目

#### 项目初始化

1. 创建项目，选择 `K8s YAML`，填写名称、编码、描述和项目成员。
2. 进入项目工作区，默认显示服务列表和环境列表。
3. 新建服务时提供三个明确入口：`手工输入`、`从代码库同步`、`使用模板新建`。

#### 手工输入服务

1. 填写服务名称和服务编码。
2. 在 YAML 编辑器粘贴一个或多个 Kubernetes manifest，支持 `---` 多文档。
3. 点击解析/校验，前端显示资源类型、资源名称、容器、镜像和可替换镜像字段。
4. 配置默认镜像地址、构建配置和服务描述。
5. 保存生成不可变服务 Revision；后续编辑必须生成新 Revision，旧 Revision 可被运行记录引用。

#### 从代码库同步单个服务

1. 选择平台统一代码源、仓库、Branch/Tag/Commit。
2. 使用目录浏览器选择服务目录，而不是手工猜文件路径。
3. 平台读取该目录下 YAML 文件，按文件名排序并合并解析。
4. 预览 Commit、文件清单、资源、组件和镜像；确认后创建服务 Revision。
5. 保存代码源、仓库、目录、固定 Commit 和文件摘要，后续 Webhook 可按目录更新服务。

#### 从代码库同步多个服务

约定一个根目录下每个一级子目录为一个服务，例如：

```text
freestyle-k8s-specifications/
  db/deployment.yaml + service.yaml
  redis/deployment.yaml + service.yaml
  result/deployment.yaml + service.yaml
  vote/deployment.yaml + service.yaml
  worker/deployment.yaml
```

同步页面展示目录树和服务预览表，允许勾选多个目录、修改服务编码、排除文件，然后一次性创建多个服务和 Revision。单个目录内的 YAML 必须来自同一 Commit。

#### 使用模板新建

1. 从模板库选择 YAML 模板。
2. 页面左侧显示模板文件/资源结构，中间显示 YAML 编辑器，右侧显示变量表单。
3. 变量支持字符串、选项、镜像、文件和 Secret 引用；Secret 只保存凭据引用。
4. 保存服务时记录模板版本和变量快照。
5. 模板发布新版本后，通过“应用到服务”显式更新，不隐式覆盖线上 Revision。

### 3.2 Helm Chart 项目

1. 创建项目并选择 `Helm Chart`。
2. 新建服务时选择 Chart 仓库、Chart 根目录和 Branch/Tag/Commit，或从模板库创建。
3. 解析 `Chart.yaml`、`values.yaml`、`values-*.yaml` 和 `templates/`，展示 Chart 元数据、模板数量、变量键和镜像字段。
4. 构建配置与 Chart 定义分离，镜像构建结果通过环境服务覆盖注入。
5. 环境中按项目、环境、服务三级 values 合并，发布前显示 `helm template` 资源 Diff。
6. 工作流执行 `upgrade --install --atomic --wait`，页面记录 release、revision、资源状态和回滚入口。

### 3.3 主机应用项目

1. 创建项目并选择 `主机应用`。
2. 服务配置包含代码库、构建产物、制品地址、部署目录、部署/启停/探活/回滚脚本。
3. 环境绑定主机组和标签，页面展示在线 Agent、批次策略和探活状态。
4. 工作流执行构建、制品校验、滚动批次发布、探活和失败回滚。
5. 页面按主机展示版本、任务、日志和失败原因。

## 4. 前端信息架构（80% 对齐范围）

### 4.1 全局导航

```text
平台首页 | 项目 | 代码源 | 模板库 | 集群 | 主机与 Agent | 构建 | 运行记录 | 效能 | 权限中心
```

平台级代码源、凭据、模板和集群只在平台菜单管理；项目页面只能选择被授权的资源，不能重复创建公共代码源。

### 4.2 项目列表

页面采用 Zadig 的项目工作台风格：

- 顶部：项目搜索、交付类型筛选、创建项目。
- 列表：项目名称、编码、类型、服务数、环境数、最近运行、负责人和状态。
- 点击项目进入项目工作区；权限不足的项目不出现在列表，也不能通过 URL 访问。

### 4.3 项目工作区

固定为以下项目内导航：

```text
概览 | 服务 | 环境 | 工作流 | 运行记录 | 制品 | 变量与模板 | 设置
```

概览展示服务、环境、运行成功率、最近失败节点和待审批发布。服务、环境和工作流页面不能互相隐藏关键上下文。

### 4.4 服务页面

服务页不再只显示表格，采用三栏结构：

```text
左侧服务树/目录       中间定义编辑器                 右侧服务信息
---------------------------------------------------------------
服务目录                YAML/Helm/主机定义编辑器       组件列表
  payment               Revision/差异                  镜像地址
  order                 格式校验结果                   构建配置
                                                         环境覆盖
底部：Revision 历史、Webhook 状态、环境更新
```

服务列表支持按目录分组、搜索、状态筛选和批量导入。服务详情必须能切换 Revision、查看内容摘要和比较两个版本。

### 4.5 新建服务向导

第一步是类型入口卡片：

```text
[手工输入] [从代码库同步] [使用模板新建]
```

第二步根据入口显示对应表单：

- 手工输入：服务名称、编码、YAML 编辑器、解析结果、镜像字段。
- 代码库同步：代码源、仓库、Branch/Tag/Commit、目录树、文件选择、单服务/多服务模式、预览。
- 模板新建：模板版本、变量表单、渲染预览、自动同步开关。

第三步统一显示确认摘要：服务、项目类型、来源、Commit/模板版本、组件、镜像、权限范围和将要生成的 Revision。

### 4.6 环境页面

环境不是只有一个集群下拉框，而是环境服务矩阵：

- 环境列表：开发、测试、预发布、生产；显示集群/Namespace 或主机组、健康状态、最近发布。
- 环境详情：服务列表、当前 Revision、镜像、实例数、变量组和服务覆盖。
- `环境更新`：选择一个或多个服务、目标 Revision、镜像覆盖和副本数，先预览 Diff 再提交。
- 生产环境：显示审批策略、审批人、发布窗口和回滚版本。

### 4.7 工作流页面

工作流采用 DAG 画布和右侧节点配置抽屉：

```text
代码拉取 -> 构建 -> 测试 -> 人工审批 -> 部署 -> 通知
              |                    |
              +--> 安全扫描 -------+
```

节点支持 build、test、yaml deploy、helm deploy、host deploy、approval、notify 和插件。每个节点配置输入、超时、重试、资源、变量和权限，保存前执行无环及项目类型校验。

### 4.8 运行详情

- 顶部显示运行号、触发人、Commit、Revision、目标环境和整体状态。
- 中间显示可点击 DAG，节点颜色区分等待、运行、成功、失败、跳过和审批。
- 下方使用标签页：实时日志、测试报告、构建产物、渲染 Diff、资源状态、审计事件、AI 根因分析。
- 失败节点先显示确定性错误分类和证据，再显示可选 AI 建议；AI 不能自动审批、部署或回滚。

## 5. AxiOps 当前实现与目标差距

| 能力 | 当前状态 | 目标 |
| --- | --- | --- |
| 三类项目 | 已有项目类型和基础工作区 | 页面按项目类型隐藏不适用字段 |
| 服务创建 | 已有三种 source_type 和 Revision API | 改为三步向导、三栏服务页和组件模型 |
| 单服务导入 | 已有预览/导入和目录单层浏览 | 目录选择自动收集 YAML，并展示资源树 |
| 多服务导入 | 尚未实现 | 根目录一级目录批量预览、批量创建和部分失败重试 |
| YAML 解析 | 后端已有组件/镜像解析 | 增加前端资源树、镜像替换点和语法/安全错误定位 |
| 模板 | 当前只有内置起始 YAML | 模板库、版本、变量、应用到服务和审计 |
| 环境 | 已有环境和服务覆盖 API | 环境服务矩阵、环境更新、Diff 和回滚入口 |
| 工作流 | 已有 DAG 编辑和运行 | 按 Zadig 节点配置抽屉补齐 test、制品、变量和触发器 |
| 权限 | 已有后端和权限中心前端 | 页面、项目、服务、环境、集群、构建和工作流全部按范围过滤 |
| 代码源 | 已有公共代码源和仓库下拉 | 统一代码源选择、分支/Tag/Commit、Webhook 状态 |

## 6. 需要补齐的领域与接口

### 6.1 服务组件

新增 `service_component` 读模型或等价 JSON 快照，至少包括 `service_id`、组件名、资源身份、容器名、镜像路径、当前镜像和可替换字段。Revision 生成时同步更新组件摘要。

### 6.2 目录同步

建议接口：

```text
GET  /api/v1/code-sources/{id}/repository-files
POST /api/v1/services/{id}/yaml-import/preview
POST /api/v1/projects/{id}/yaml-services/import/preview
POST /api/v1/projects/{id}/yaml-services/import
```

批量导入请求必须包含 `repo_path`、`ref`、`root_path`、选中的服务目录和预期 Commit。服务端重新读取固定 Commit，按目录边界收集 YAML，返回逐服务预览；任何一个目录越界或 Commit 漂移都拒绝提交。

### 6.3 模板中心

建议增加模板类型、模板版本、变量定义、模板文件摘要、实例绑定和应用记录。模板版本不可变，服务实例只引用版本号；模板更新必须由用户确认生成新服务 Revision。

### 6.4 版本和环境

环境服务覆盖必须始终引用不可变服务 Revision、镜像 digest 和变量组版本。环境更新先返回渲染结果和 Diff，确认后写入工作流运行快照。

## 7. 分阶段实施计划

### P0：产品结构重构

1. 项目工作区增加运行记录、制品、变量与模板入口。
2. 服务页改为左树、中编辑器、右组件信息和 Revision 历史。
3. 新建服务改为三步向导，按项目类型显示字段。
4. 统一中文文案、空状态、错误提示和权限禁用态。

### P1：YAML 服务完整对齐

1. YAML 多文档解析、组件/镜像树和前端错误定位。
2. 代码库目录树、单服务目录同步和当前目录 YAML 全选。
3. 一级目录批量同步、多服务预览、批量 Revision 和失败重试。
4. Revision Diff、环境更新入口和服务环境矩阵。

### P2：Helm/模板对齐

1. Chart 文件树、values 参数表、模板变量和渲染预览。
2. 模板库 CRUD、版本、变量校验、应用到服务和审计。
3. Helm 环境 values 合并、发布 Diff、release revision 和回滚。

### P3：工作流和运行体验

1. DAG 节点配置抽屉、触发器、并行、重试、测试和通知。
2. 运行详情 DAG、实时日志、测试报告、Diff、产物和资源状态。
3. 失败分类、AI 根因分析证据卡片和权限范围验证。

### P4：企业验收

1. 开发、测试、运维三类账号的项目/服务/环境/集群范围验收。
2. 10 个测试集群、多云网络、镜像仓库、Git webhook 和通知渠道 E2E。
3. 100+ 开发人员并发查看、构建排队、日志读取和权限过滤压测。

## 8. 验收标准

- 新建 K8s YAML 服务可以分别通过手工、单目录同步、多目录批量同步和模板四条路径完成。
- 一个服务目录下的多个 YAML 文件能一次预览并生成一份 Revision；同级多个目录能生成多份服务 Revision。
- 页面可以查看资源、组件、镜像、Commit、Revision、环境覆盖和 Diff；历史 Revision 不被编辑覆盖。
- YAML、Helm、主机项目只显示对应的服务和环境配置，不出现类型不相关字段。
- 用户只能看到被授权项目、服务、环境、集群和工作流；只读用户没有创建、编辑、运行、审批和回滚入口。
- 构建、测试、部署和通知节点在运行详情中显示状态、日志、产物和失败原因。
- 所有新功能完成单元测试、接口测试、前端静态检查和浏览器 E2E 后，才能在 `PROGRESS.md` 标记完成。

## 9. 当前结论

上一轮实现的三种 source_type 和目录单层浏览只是 P1 的前置能力，不等于 Zadig 80% 对齐。下一轮应先完成 P0 服务页面和新建向导，再实现 P1 多服务目录同步；模板中心和完整工作流节点不能用一个内置 YAML 文本框替代。
