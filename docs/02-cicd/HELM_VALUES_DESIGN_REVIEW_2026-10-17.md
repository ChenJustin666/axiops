# Helm 多环境 values 设计复核

用户确认后已实施首版主流程：默认当前环境 values、文件来源与 Git 三方比较、最终 values / YAML 预览、环境共享 values、深层参数同步、创建环境时配置服务。存量配置原文保留，不静默迁移，也不自动部署。使用步骤见 [Helm 多环境配置](HELM_MULTI_ENV_VALUES_2026-10-17.md)。任意 schema 自动表单及真实浏览器/集群验收尚未完成。

## 建议采用的使用流程

### 1. 服务维护原生 Chart

新建 Helm 服务保持两个入口：模板、代码仓库。保留 `Chart.yaml`、`values.yaml`、`templates/` 和子 Chart 原生结构。

服务定义中的 `values.yaml` 是 Chart 默认参数；选定环境后的“当前环境 values”是该环境配置。两者名称和范围必须清楚，不能都叫 values.yaml 却让用户猜保存影响谁。

左侧服务列表，中央默认当前环境 values。原生 Chart 文件通过“Chart 源码”切换查看和编辑；源码更新、版本选择、镜像映射收进对应入口。顶部只常驻环境名称、集群/Namespace、当前 Chart 版本及保存状态，减少重复目录和工具条。

### 2. 创建环境时同时配置服务

选择环境名称、集群、Namespace → 选择已有服务 → 每个服务配置 values → 预览 → 保存。首次项目初始化允许一次完成这些步骤；后续新建生产环境复用同一入口。

每个服务支持：直接填写/粘贴 values、从已固定 Chart 的文件中选择（如 `values-qa.yaml`）、从代码仓库读取指定 values 文件、参考已有环境配置。不是强制每人学习一张大型表单，也不额外要求去另一个页面“加入环境”。

引用测试环境仅提供配置起点，目标环境仍明确独立保存；域名、Nacos namespace、数据库、Secret 引用等须核对，不能自动推断生产正确值。自定义环境名不应强制映射为 test/prod Spring Profile。

原生 Chart 若有 `values.schema.json`，可据其定义提供表单；平台内置 Java/Nacos 模板提供自己的字段分组。任意第三方 Chart 保留原生 values 编辑，不能把 Java 字段强行用于 Node/Python/Go Chart。

### 3. 日常只修改选定环境

选择测试环境 → 选择服务 → 修改该环境 values（副本、资源、env、Nacos、路由等）→ 查看最终 values / 渲染 YAML → 保存当前环境配置 → 按工作流发布。

values 可只写差异，也可写完整配置。默认编辑该环境保存的原文，提供只读“最终 values”及“渲染 YAML”；不得将预览合成结果自动回写成新的环境覆盖，否则所有默认值被固定，后续 Chart 新默认值会被旧值挡住。

保存不升级其他环境、不写共享模板、不自动运行工作流。保存完成显示“配置已保存，待发布”；运行资源页显示上次实际发布的版本，不能将未发布草稿冒充运行配置。

### 4. 环境共享配置

配置位置为“环境设置 → 共享 values”，优先用于同一环境多个服务使用的 Nacos 地址、数据库地址等。不同环境各有一份，避免平台全局变量让测试地址进入生产。

明确优先级：Chart 默认 values ＜ 此环境共享 values ＜ 此服务在此环境的 values。工作流最终选择的制品在受控镜像路径注入固定摘要；凭据路径独立保护，普通 values 不得覆盖凭据绑定。Release、集群、Namespace 来自平台目标，不允许通过任意 values 改发往其他环境。

共享值更新先计算受影响服务，展示哪些服务被自身覆盖而不受影响，预览差异和配置校验后再保存。不因共享配置保存而自动发布；批量发布复用既有工作流。若同一批声明全量保存，权限/校验/并发冲突任一失败不应只保存一部分。

### 5. Git 同步区分 Chart 与环境 values

Chart 来源与 values 来源可以是不同仓库、分支和路径，分别记录固定 Commit。Chart 更新不自动替换环境 values；只修改 `values-prod.yaml` 时无需让用户把整个 Chart 当作新版本升级。

从仓库读取 values 后保存快照。平台允许编辑当前环境，之后 Git 再改，按“上次导入内容 / 当前平台内容 / 新 Git 内容”比较；发生同一路径冲突时逐项处理或明确选择替换，不能用单一“接受全部仓库更新”覆盖未合并的平台改动。保持平台修改不自动推送 Git。

首版优先实现主动检查同步；不增加后台自动发布。分支移动、值来源被撤权、读取失败、目标配置被他人修改都阻止陈旧预览提交。

### 6. 环境对比与复制

测试 → 生产同步按实际参数路径选择，如 `resources.limits.memory`、`probes`，保留目标未选择的配置。目标独有 HPA/PDB/Ingress 不因普通同步而消失。

对象按路径深度处理，数组遵循 Helm 的整体替换语义并显示整项差异，不盲目按下标合并。删除覆盖表示恢复继承；禁用资源使用 Chart 支持的 enabled 开关；null 按 Helm 语义验证，不把删除、空字符串和 null 混为一谈。

凭据正文不参与普通复制；目标环境独立绑定 Secret/凭据。域名、数据库、配置中心等差异不以任意键名猜测安全，展示真实差异及来源，由用户核对。生产发布继续复用测试通过的镜像摘要，目标 values 保持生产配置。

## 实施前的主要差距（调研留档）

| 项目 | 当前状态 | 建议调整 |
| --- | --- | --- |
| 原生 Chart 文件 | 已能递归导入与查看，Git Chart 更新有比较 | 保留，源码入口次于环境配置 |
| 环境 values | 每服务/环境独立文本；新环境将整个默认 values 复制进草稿 | 改为明确的环境覆盖来源，独立提供最终 values 预览；存量配置原样保留 |
| values 文件来源 | 仅 Chart Git 同步，环境 values 无独立来源/更新流程 | 增加文件选择、独立固定 Commit、快照和冲突比较 |
| 环境创建 | 创建服务与环境服务配置尚未形成统一 Helm values 步骤 | 创建环境时选服务并配置，不要求创建后再找绑定入口 |
| 参数编辑 | 原生 values；镜像映射/继承参数同时展示 | 默认原生编辑，schema/内置模板可切表单，高级项折叠 |
| 共享配置 | 已有项目/服务/环境路径变量，当前 values 优先 | 收敛为明确环境共享 values 与来源说明，预览受影响服务，勿直接加更多重叠层 |
| 环境同步 | 仅按顶层 key 替换，如整个 resources | 参数路径比较/选择，明确数组整体替换和目标独有项保留 |
| Chart 编辑校验 | 依赖模板库默认 values 即可渲染 | 原生 Chart 应区分结构/语法检查与带当前环境 values 的部署校验，允许合法 required/schema 依赖环境输入 |
| 运行版本呈现 | 已有环境绑定/运行快照机制 | 页面明确待发布配置与实际已发布状态，避免误读 |

## 推荐实施顺序与验收

1. 收敛“选环境 → 当前服务 values”的主界面；加入最终 values / YAML 预览，隐藏低频源码/映射配置。先保持现有配置内容与部署行为，不静默改写存量覆盖。
2. 完成创建环境选服务、从 Chart/仓库 values 文件配置及当前环境保存闭环；随后补 values 独立同步与冲突处理。
3. 完成环境共享 values、影响范围与深层参数同步，统一已有变量优先级。存量迁移前对所有服务用相同固定镜像渲染前后比较，有差异不得自动迁移。
4. 验证新测试/生产环境的值分开、values 读写和同步不串环境、来源版本冻结、并发保存失败无部分写入、平台改动不丢失、Git 更新不隐式部署、生产镜像固定摘要、Secret 不出现在普通 values/差异里。

真实 Helm 发布、失败恢复与回滚使用固定 Chart＋最终 values＋目标＋镜像摘要的快照，历史不回读浮动 Git。每一步完成后再进行桌面/窄屏实际点击与真实测试集群验收，不把组件测试当作发布成功。
